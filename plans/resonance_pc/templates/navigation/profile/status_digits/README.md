# 玩家信息状态栏数字模板

这组模板目前仅用于离线评估，尚未接入用户信息识别 Action。包含 `0.png`–`9.png` 和 `slash.png`，均为 12×16 单通道二值字形，不包含截图背景、加号或角色信息。

素材由游戏资源中的 `SourceHanSansCN-Bold` 字体生成；字体文件不入库。生成器校验字体 SHA-256，并在 1280×720 参考分辨率下，以 16px 字号、120 灰度阈值裁切并居中字形：

```powershell
.\.venv\Scripts\python.exe tools/generate_profile_status_digit_templates.py ".pytest_tmp/event_templates/assets/SourceHanSansCN-Bold.ttf"
```

用户提供的两张 1332×802 截图中，客户区均为 `(26,56,1280,720)`。保存在 `tests/fixtures/profile_status_digits/` 的六个裁图只含状态字段，不含 UID；两组字符分别是 `258/286`、`58/864`、`7/998` 和 `148/286`、`45/864`、`7/1003`。以亮色分割、连通域逐字居中、模板相关匹配及 ±2px 搜索验证，37 个可见字符的第一候选均正确；第一张图最低分数约 0.754，第二张图最低分数约 0.726（数字 `1`），两张图的最小领先差约 0.026。

这仍是**两张截图**的离线校准，不足以制定运行时阈值或证明其他数值也稳定。第二张图补齐了数字 `0`、`1`、`3` 的实例，但 `1` 低于首图暂用的 0.75 分数线。单独改强 `0` 模板会把首图的两个 `9` 错判为 `0`，因此没有为了新图调改模板。接入运行流程之前，还需要更多不同数值、不同帧的样本，尤其检查 `0/9`、`6/8` 的分差和斜杠是否被裁切；不确定时应失败而非猜测数值。
