# 独立更新器

关闭主界面后，运行安装目录中的 `更新.exe`。在窗口中选择正式版（`vX.X.X`）或
测试版（例如 `v1.20.1-E.1`），然后点「继续」。正式版为默认选项。每次启动都可以重选，
点「取消」或关闭窗口即可退出。程序先启动独立临时助手，原窗口退出后由助手完成更新。

助手只检查所选通道的 CPU 完整包。测试版沿用上一正式版的版本号，编号从 1 开始按数字递增。
选择测试版通道时，可以从同基础版本的正式版切换到编号测试版。
如果手上的旧版更新器仅识别 `-E`，请先从 GitHub Release 下载首个编号测试版的完整包，之后可继续使用包内更新器。
启用 VPS 下载源的发行包会先查询 VPS。发现新版后自动排队，正式版与测试版共用一个下载名额。
窗口会显示前面还有几位，轮到后自动下载。排队或下载期间可按 Ctrl+C 取消。
VPS 服务故障时，助手会切换到 GitHub。已确定版本的更新会继续下载同一版本。
助手会校验固定版本 ZIP 的 SHA-256、解压目录结构和包内版本。
上述步骤成功前不会改动旧发行文件。

安装会替换 `runtime`、`plans`、`models`、根配置、启动器、更新器及发行说明。
`user-data`、`gui-settings.ini`、`logs` 和其他非发行文件保留。自行修改的 Plan
会随旧发行文件进入备份，不会自动合并到新版。

## 失败恢复

- 同一安装目录只允许一个更新助手执行下载和安装。
- 文件替换前会在 `.update-work/transactions/<编号>/backup` 备份旧内容。
- 安装失败会回滚，恢复记录写在同目录的 `transaction.json`。
- 更新器自身先完整备份，再原子覆盖，避免中断后根目录没有更新器。
- 如果回滚被文件占用阻止，请释放占用后重新运行 `更新.exe`。程序先恢复上次
  更新，提示恢复完成；再次运行才会检查新版。
- 最近一次成功更新的备份保留，下一次成功更新后清理更旧的成功备份。
- 临时助手所在目录不会在运行期间删除；后续更新会清理超过一天且未运行的助手。

更新器及临时助手的详细错误和阶段记录共用安装目录 `logs/` 下本次
`aura_session_*.log`，结束或失败时会显示具体路径。助手在旧进程交接后继续追加
同一文件，无需分别查找 `logs/updater/` 和助手日志；旧版更新日志仍保留。
出现失败时不要手动删除 `.update-work`，其中可能保存着恢复旧版必需的文件。

CPU 包下载不依赖 GPU/overlay 资产。更新器不迁移旧 GPU 安装，不兼容旧版
更新协议。更新器不自动启动游戏，也不会关闭其他安装目录的 Aura 或游戏进程。
