# OCR recognition width and padding benchmark

用同一组真实截图分别比较四种识别策略，检测和方向分类保持不变：

| 策略 | width_mode | batch_mode |
|---|---|---|
| baseline | legacy | fixed |
| width_only | adaptive | fixed |
| batch_only | legacy | adaptive |
| combined | adaptive | adaptive |

候选配置为最小宽度 160、按 32 对齐、识别最大批次 8、每次拆批最少节省 25%
输入面积。识别高度、等比缩放、归一化、CTC 解码和长文本最大宽度策略保持原状。
框架配置保留两个独立开关。本次实验完成后，默认策略调整为 `legacy/adaptive`，
只启用自适应分批；`legacy/fixed` 仍可显式配置恢复实验基线。

运行方式（仓库根目录）：

```powershell
$recognitionTemp = Join-Path $PWD '.pytest_tmp/ocr-recognition-ablation'
New-Item -ItemType Directory -Force $recognitionTemp | Out-Null
$env:TEMP = $recognitionTemp
$env:TMP = $recognitionTemp
$env:TMPDIR = $recognitionTemp
$env:AURA_LOG_ROOT = Join-Path $recognitionTemp 'logs'
& ./.venv/Scripts/python.exe -m tools.benchmark_ocr_recognition --output .pytest_tmp/ocr-recognition-ablation
```

CPU 8 个 ORT 算子内线程、关闭算子内/间自旋，OpenCV 配置保持原状。
两个轮次分别随机安排四个策略，每个策略使用独立进程，全部串行执行。
每个引擎完成实际启动预热后，四个样本各自预热 3 次，再计时 20 次，
共 640 次调用。样本为已有数字单行、中文单行、小区域及整屏，前两者直接识别。
时间包含完整 OCR、解析、阶段计时和输入形状诊断，不含截图、文件解码、
模型加载/预热、输出比较和报告序列化。

每次记录实际识别输入 `[N,3,H,W]`、每条文字缩放后的有效宽度、补零比例、
模型输入元素总数和分批次数。输出按检测多边形对齐，分别检查文字、数量、
多边形、矩形、中心点和置信度，记录置信度差及 0.5/0.8/0.9 阈值跨越。
还保留轮内重复和跨轮次稳定性、逐区域置信度范围及原始结果。
这是与原策略的结果对比，不是带独立人工标注的准确率评估。

原始结果为 `.pytest_tmp/ocr-recognition-ablation/run-*-*.json`，汇总为 `summary.json`、
`summary.csv`，逐次数据为 `calls.csv`。包含模型、样本和源码 SHA256 及有效会话参数。
每轮相对基线的收益单独保留；进程分开且宿主负载可能变化，未减少计算量却出现的
耗时变化不能直接归因于优化。两项收益也不能简单相加。

## 2026-10-22 结果

环境为 Ryzen 9 9950X，ONNX Runtime 1.27.0，当前 PP-OCRv6 small CPU 模型。
第一批隔离进程实验中，中文单行的输入形状完全没变，却出现约 22% 的耗时差，
说明进程之间负载波动较大。因此追加共享会话的交错对照，作为性能判断的主要依据：

```powershell
& ./.venv/Scripts/python.exe -m tools.benchmark_ocr_recognition --paired --output .pytest_tmp/ocr-recognition-ablation-paired
```

每轮只加载一组检测、方向分类、识别会话，四个策略分别预热后共享这些会话。
每张样本每四次迭代随机安排基准顺序并循环轮换，20 次迭代中每个策略在每个位置
各出现 5 次；两轮共额外 640 次调用。两个实验共 1280 次计时调用，全部串行。
交错数据及逐区域对比位于 `.pytest_tmp/ocr-recognition-ablation-paired/`。
原独立进程版本工具的源码快照与记录的 SHA256 一致，保存在
`.pytest_tmp/ocr-recognition-ablation/benchmark_ocr_recognition.isolated.py`。

下表为交错实验两轮的总耗时均值（ms），括号为相对旧策略的耗时减少百分比；
负百分比表示变慢。

| 样本 | 旧策略 | 仅改宽度 | 仅改分批 | 两项组合 |
|---|---:|---:|---:|---:|
| 数字单行 | 7.70 | 5.61（27.2%） | 7.69（0.1%） | 6.04（21.5%） |
| 中文单行 | 7.50 | 7.41（1.2%） | 7.52（-0.3%） | 7.39（1.5%） |
| 小区域，3 行 | 23.82 | 23.58（1.0%） | 24.35（-2.2%） | 23.90（-0.3%） |
| 整屏，40 行 | 416.20 | 380.37（8.6%） | 348.83（16.2%） | 323.36（22.3%） |

整屏仅分批的两轮收益分别为 16.3% 和 16.1%，组合分别为 22.6% 和 22.0%；
仅宽度分别为 6.7% 和 10.3%。数字单行仅宽度的两轮收益为 29.4% 和 24.2%。
中文单行和小区域的实际张量与批次完全不变，这几组小幅耗时变化不视为有效收益。

### 实际输入与结果变化

- 数字单行从 `1×3×48×320` 降至 `1×3×48×192`，输入元素减少 40%。
  文字、框和中心点不变；置信度最大绝对变化约 `0.0000164`。
- 中文单行始终为 `1×3×48×320`；小区域始终为 `3×3×48×352`，结果完全一致。
- 整屏旧策略为五批，各批 8 条，宽度分别为 `320/320/320/448/928`。
  仅宽度变为 `160/224/288/448/928`，总输入元素减少约 12.3%。
- 整屏仅分批将最后一批拆成 `5×3×48×512` 和 `3×3×48×928`，其余不变，
  总输入元素减少约 11.1%，从五批变为六批；组合总输入减少约 23.5%。
- 两种宽度自适应配置均将整屏中一个低置信度字符由 `S` 改为 `à`，
  置信度从约 `0.1956` 变为 `0.1710`；另一处文字 `0` 的置信度从约 `0.6030`
  变为 `0.6871`。不能将这种变化解释为准确率提升或下降，样本未独立标注。
- 单独分批的全部文字、数量、多边形、矩形和中心点保持一致；整屏最大置信度
  绝对变化约 `0.00809`。其他三组结果完全一致。
- 所有策略轮内重复和跨轮次结果均稳定。没有观察到置信度跨越 0.5、0.8、0.9，
  但这不代表其他筛选阈值不会受影响。

旧策略的四组完整原始/解析结果与上一轮阶段基准完全一致，验证配置回退兼容。
框架默认采用 `legacy/adaptive`，只启用本次验证的自适应分批，
不自动启用会改变文字的宽度候选。默认配置为：

```yaml
ocr:
  recognition:
    width_mode: legacy
    batch_mode: adaptive
```

宽度自适应保留为可选项，适合先在明确的短数字/标签样本上继续验证；
切回 `batch_mode: fixed` 即恢复本次基线。当前结论仅覆盖四组截图，不能代替
更广泛的人工标注准确率评估。默认策略调整后的相关回归共 217 项通过；
真实模型四组样本分别验证默认配置和固定分批覆盖，完整结果均与此前相应实验一致。
