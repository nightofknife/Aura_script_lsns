# OCR textline orientation benchmark

测量单次调用 `use_textline_orientation: true/false` 的差异，文字检测保持开启，
识别使用框架当前默认的旧宽度和自适应分批。分类开关不改变启动加载和预热。

在仓库根目录运行：

```powershell
$orientationTemp = Join-Path $PWD '.pytest_tmp/ocr-orientation-benchmark'
New-Item -ItemType Directory -Force $orientationTemp | Out-Null
$env:TEMP = $orientationTemp
$env:TMP = $orientationTemp
$env:TMPDIR = $orientationTemp
$env:AURA_LOG_ROOT = Join-Path $orientationTemp 'logs'
& ./.venv/Scripts/python.exe -m tools.benchmark_ocr_orientation --include-rotated --output .pytest_tmp/ocr-orientation-benchmark
```

采用 CPU 8 个 ORT 算子内线程、关闭自旋，OpenCV 配置保持原状。
每轮创建一组会话并完成现有启动预热，开关两组共享同一个管线和模型会话。
两轮独立进程顺序执行，每张样本每组预热 3 次，再交替 AB/BA 运行 20 对调用。
同时验证省略参数的调用与显式 `true` 完全一致。

默认四组真实截图/区域包含数字单行、中文单行、小区域和整屏，前两组使用
`recognition_only`，作为两个模式本来就都不执行方向分类的对照。
`--include-rotated` 额外加入小区域截图旋转 180°的派生诊断样本，
用于观察倒置文字影响；它不是独立采集的真实截图。包含该样本时共 400 次计时调用，
其中原始真实样本 320 次，派生样本 80 次。

总耗时包含已预热管线的预处理、推理、后处理、结果解析和阶段/输入形状计时，
不含截图、文件解码、会话加载/预热、异步桥接和结果比较/序列化。
用共享管线交错执行减少进程间负载波动；仍保留每轮均值、总 P50/P95 和逐次数据。

每次断言：关闭分类时所有 `ori_*` 调用次数为零，完整 OCR 的检测和识别仍执行；
直接识别模式的检测和分类始终为零。还验证开关调用不会改变共享引擎和预热成功状态。
原始结果包含文字、置信度、多边形、矩形和中心点，按检测多边形对齐比较，
记录置信度差和 0.5/0.8/0.9 阈值跨越，以及轮内和跨轮次结果稳定性。
开关结果一致性不等同于经过人工标注的准确率评估。

原始结果在 `.pytest_tmp/ocr-orientation-benchmark/run-*.json`，
汇总为 `summary.json`、`summary.csv`，逐次明细为 `calls.csv`；
`artifact-sha256.json` 保存结果文件哈希，运行记录另含模型、样本和源码哈希。

## 2026-10-22 本机结果

Ryzen 9 9950X，16 物理核/32 逻辑处理器，Windows，ONNX Runtime 1.27.0，
CPUExecutionProvider，PP-OCRv6 small；ORT 8 线程/关闭自旋，OpenCV 32 线程。
每个样本每组累计 40 次计时，共 400 次；默认省略参数与显式开启完全一致。

| 样本 | 开启均值 ms | 关闭均值 ms | 耗时减少 | 开关结果 |
|---|---:|---:|---:|---|
| 数字单行，直接识别 | 5.86 | 5.93 | -1.1% | 完全一致 |
| 中文单行，直接识别 | 7.03 | 7.00 | 0.5% | 完全一致 |
| 小区域，3 行 | 21.92 | 17.10 | 22.0% | 完全一致 |
| 整屏，40 行 | 322.23 | 281.68 | 12.6% | 完全一致 |
| 小区域旋转 180°，派生诊断 | 15.80 | 12.54 | 20.6% | 完全一致，但只返回 `i` |

“完全一致”包含全部原始及解析字段：文字、数量、置信度、多边形、矩形和中心点；
最大置信度差为零。所有组在轮内重复和跨轮次均稳定，没有观察到阈值跨越。
四组原始样本的开启结果也与之前“旧宽度＋自适应分批”实验的完整结果一致。

小区域两轮耗时减少 23.3% 和 20.2%，整屏分别为 10.1% 和 15.2%。
开启时方向分类阶段均值分别为 4.74 ms 和 43.66 ms，关闭后各 `ori_*` 阶段为零，
完整 OCR 中检测和识别仍执行。直接识别两组的检测和分类本来就为零，
小幅耗时变化视为测量波动，不视为优化收益。

旋转派生样本只返回一个 `i`，而原图返回三行文字，因此它不能证明对倒置中文
的识别质量可靠。开关在这个派生输入上结果相同，也不代表关闭方向分类对所有
倒置文字无影响。框架默认继续开启分类，固定正向 UI 可按调用关闭。

启动逐阶段预热在两个进程中各执行一次，均覆盖检测、方向分类（batch 1/8）和
识别（batch 1/8）；调用开关没有创建或卸载模型会话。相关回归共 261 项通过。
