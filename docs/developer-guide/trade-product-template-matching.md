# 购买商品图标识别

购买商品身份由 `_trade_buy_selection.py` 识别，货运四模式和客运倒货共用现有买货入口。商品名称 OCR 和错字映射已移除，不保留商品 OCR 回退；买入按钮及结算流程沿用现有确认方式。

## 模板与匹配

- `data/meta/trade_product_templates.json` 覆盖 229 种商品，228 种支持识别。
- `templates/trade_products/` 包含 456 张 available/selected 模板，均为带游戏底纹、固定裁剪的 80×56 RGB PNG，无 alpha 或蒙版。
- 彩色 `TM_SQDIFF_NORMED`，置信度为 `1-score`，接受门槛为 0.92；不使用灰度、亮度归一化或其他商品身份辅助判定。
- 全库模板在同一位置竞争，先确认最高分身份再过滤待购 ID，不能让待购商品的弱匹配覆盖更可靠的其他商品身份。
- 宝石工艺品（ID 67）缺少配置图标，明确标为 unsupported 并告警跳过，不用相似素材替代。

## 购买流程

列表从当前位置向下扫描，不归顶。点击后重新截图，只用同商品 selected 模板在原行确认；最多补点一次，且补点前仍须明确为 available。

部分商品漏选时购买已确认部分，并沿原路线继续。全部漏选时跳过协商和买入，确认返回商店后继续。漏选不重规划或重复用书；原计划的书只执行一次。取消、用书未确认或成交失败仍阻断后续发车，并保留已耗书记录。

结果包含 `buy_result=complete/partial/skipped`、已确认商品、漏选商品和 warnings。路线汇总给购买 warnings 补充航段索引。漏选后原路线的预计收益不代表已实现收益。

## 生成与验证

`tools/build_trade_product_templates.py` 是离线素材生成工具，使用独立开发环境中的 UnityPy 读取游戏资源。运行时只读取已提交的 PNG 和 JSON，不依赖 UnityPy 或本机解包目录。

配套测试覆盖选择、同位置竞争、点击确认、取消、部分/零选中、用书记录以及四模式货运和客运接线。真实截图 fixture 只有 8 张裁块，不能据此宣称所有商品已通过游戏实机验收。
