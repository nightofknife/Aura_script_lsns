# 公共交互服务

`plans/aura_base/interaction` 承接查找后点击、点击回执、效果确认和普通页面转场。它依赖公共 `app` 与 `observation`，识别仍由观察服务调用 vision/OCR。帧、预算、确认状态和输入记录属于一次操作，不保存在单例服务字段中。

## 查找后点击

`find_template_and_click` / `find_text_and_click` 在同一 operation scope 内完成有效观察、连续稳定、输入前校验、鼠标移动、点击和点击后等待。同步入口供同步 action 使用，异步入口通过现有受追踪 worker 执行，不创建每次调用的线程池或事件循环。

已有 `find_image_and_click`、`find_text_and_click` action 是兼容适配：保留原业务参数、默认值、bool 返回及 `required` 对应的 `StopTaskException`。注入参数末尾新增 `interaction`，不暴露为业务输入。模板解析也消耗总预算，OCR 的识别模式、方向开关与高裁剪旋转参数继续转发。

`timeout=0` 保留一次探测语义，不添加立即过期的局部截止，仍继承外层取消和预算。`timeout>0` 从路径解析前开始计时，覆盖移动与点击后等待；超时后的结果不得返回成功。即使点击已发送，后续超时或取消也不代表输入已撤销。

查找点击的 True 只表示输入调用已发送并完成本入口的等待，不证明页面、购买或生产业务成功。框架回执保留 attempted、acknowledged、call_returned 等阶段；app 返回 None 时 acknowledgement 保持未知，不能当作明确成功。服务结果的 `sent` 是历史发送事实，仍须检查 `code` 和 `phase`；发送后超时并非成功。输入技术异常和显式拒绝传播 `InteractionError`，携带原因链与回执，不降格为普通未找到。

## 点击与确认

`click` 使用有效观察的客户区坐标，并校验帧对应的目标身份。`send_input` 接受领域已经确认的同步输入回调，提供同样的 scope、目标保护和回执语义；它本身不补点。异步入口将同步输入卸载到受追踪 worker，拒绝把未 await 的协程当作已发送输入。

`confirm` / `confirm_async` 处理连续有效观察、语义/帧对等价和预算。领域可定义未知值；工坊旧入口仍仅将 None、False 判为无证据，合法的 0 不被误删。领域回调抛出的资源/识别异常继续传播，不改成普通“未找到”。

工坊的 `effect` 和 `ready` 两阶段继续分开：先取得效果证据，再取得新的连续就绪证据。记录中的 `input_attempted`、`input_acknowledged`、`effect_confirmed`、`transition_ready`、`effect_evidence`、`ready_evidence` 和原错误原因链保留。5 像素取整、1280×720 范围和 BGR 领域读图仍在计划适配层。

## 普通页面转场

`TransitionProbe` 表达 source、target 或 unknown，以及稳定键、控件证据、帧和显式允许的首帧源证据。领域提供页面分类和源控件重新定位；框架提供稳定确认和有界执行。探针前后及点击前检查 operation 内目标身份，即使旧领域读图返回的是裸数组，也不允许窗口变化后继续使用旧证据。

默认策略只允许一次点击。只有明确启用可重试的导航策略，才能在 `max_clicks` 范围内补点。每次补点重新观察源和目标，不复用旧点击点；目标已成立时不发送输入。观察、等价比较、sleep 和输入前后均受同一总 scope 限制。

`TransitionPolicy` 可配置源丢失锁存。启用时，操作局部的 `TransitionState` 必须传给逐帧探针和执行器；发送首点后，任何中间源丢失或 unknown 都永久关闭后续补点，只等待目标。不能只在稳定结果处检查，否则会漏掉中间未知帧。生产补人的现有领域分支继续保持该约束；本批没有改写其页面/按钮业务规则。

购买、投资、投币、消耗恢复品等提交不能借用普通导航的补点配置。消费后状态不明必须由领域读取后置证据；公共服务不自动重发提交，也不推断业务回滚。

## 本批迁移

| 入口 | 公共能力 | 领域继续持有 |
| --- | --- | --- |
| 两个基础查找点击 action | 观察、稳定、输入和总预算 | 资源解析、公开返回与 required 外观 |
| 黑月准备与退出 | 稳定探针、有界导航补点 | 页面状态、控件、像素等价、首步调用前提、错误码 |
| `_reforming_center_clicks.py` | 输入回执与效果/就绪确认 | 原 record 外观、坐标取整、工坊领域回调 |
| 进入指定工坊房间 | 同一 scope 下的点击与两阶段确认 | 地图定位/拖动、房间身份、选中轮廓、目标页面 |

`_template_click_transition.py` 保留既有 Python 名称作为薄兼容适配，已移除它的轮询与重试循环。黑月准备/退出公共 action 显式注入交互服务。直接 Python 调用未传服务时创建本次局部公共 facade，仍使用相同公共实现。

工坊 helper 可通过 `interaction_context(interaction, scope)` 绑定注入服务和父预算；未绑定的原料、收菜和补人调用继承当前 scope，并使用本次局部公共 facade。它们不保留旧等待内核。补人自己的“源消失后只等待”业务分支、原料提交结果与收菜结果判定未迁入框架。

## 预算与行为收紧

- 黑月每个探针保留 7 秒局部上限，并受整步总预算限制；准备为最多 `4 × (2 × 7 + 0.35) = 57.4` 秒，退出为 58 秒，仅确认就绪为 7 秒。原来每次 probe 重新获得完整预算的方式不再延长整步操作。
- 房间导航预算为 `30 + (max_search_steps + 1) × (settle_sec + 2)` 秒，包含前置读取、地图导航、选择、入口点击和确认；外层更短预算优先。拖动次数上限和拖动后的最后一次观察继续由领域控制。
- 工坊确认从第一次等待前开始计时，使用真实截止代替 `ceil(timeout/poll)` 次数。截图、识别或比较耗时不再额外延长 timeout。
- 取消传播 `CancelledError`，包括黑月共享取消检查；不把取消转换成普通页面识别失败。异步同步回调继续使用首批 OperationScope 的 drain/目标隔离机制。

本批已按后续明确授权完成 **1210 项离线测试、184 组新旧差分**，发现并修复输入验证、取消锁存和领域回执适配等边界，见[本批验证记录](interaction-batch2-validation.md)。差分中的安全收紧和诊断变化已单列，不宣称所有结果逐字节一致。本次未做实机验收、性能基准或打包；首批的验证记录继续保留其对应版本。
