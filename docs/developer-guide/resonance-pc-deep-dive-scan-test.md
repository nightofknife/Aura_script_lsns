# 识海深潜魔方布局扫描：人工对比操作说明

算法与数据流见[全魔方布局识别思路](resonance-pc-deep-dive-recognition.md)。

当前版本已实现独立的实验扫描任务，用于输出六面节点布局，再由人工与游戏画面对照。2026-09-27 抗抖版在当前棋盘连续5次完成54/54格及全部目标，含报告生成耗时30.3–48.1秒，平均35.4秒。五次与既有录像参考一致；这是同一棋盘的重复稳定性验证，尚未完成跨布局验收。

## 开始扫描

1. 将游戏客户区设为 **1280×720**，进入识海深潜的普通魔方棋盘，并等待玩家行动回合。
2. 关闭节点事件、移动选格和层旋转预览等界面，保留普通棋盘。扫描任务从这里开始，不负责进入关卡。
3. 在 GUI 中打开 **小任务 → 识海深潜**，点击 **扫描魔方布局**。
4. 等待任务停止，再点击 **打开扫描报告**。运行中可以点击 **取消**；任务会尝试释放自身鼠标输入，并保存已经取得的结果。

任务先连续两帧确认普通玩家棋盘与“重置视角”模板，再点击识别到的重置控件。等待魔方结构稳定后，建立本次扫描的坐标，先执行两轴短程标定，再进入连续拖动。输入协程、高频几何跟踪、低频内容识别和PNG写盘独立运行；内容识别使用截图当时的冻结姿态，不能套用当前姿态。控制器预测具体缺格在哪些姿态下可读，考虑界面遮挡及画面内倾斜方向，按剩余角度和反馈时效调节移动。

扫描期间请不要手动拖动魔方或触发游戏动作，以免把外部输入混入扫描轨迹。任务不点击节点、不移动玩家，也不执行改变棋盘排列的层旋转。业务界面发生变化、连续失去跟踪或没有几何响应时，会停止并保留证据。

## 参数与预算

任务入口为 `tasks:consciousness_deep_dive_scan_pc.yaml:consciousness_deep_dive_scan_pc`。以下参数可以通过任务输入调整；目前 GUI 的扫描按钮使用默认值，未提供这些参数的单独控件。

| 参数 | 默认值 | 允许范围 | 含义 |
| --- | --- | --- | --- |
| `max_steps` | 96 | 1–300 | 最多完整拖动手势次数 |
| `time_budget_sec` | 60 | 5–900 | 扫描时间预算，秒 |
| `drag_step_px` | 300 | 30–450 | 中等距离基准，实际长度按目标角度、响应增益和可用屏幕空间调整 |
| `drag_duration_sec` | 0.15 | 0.15–1 | 仅初始标定手势的计划移动时长，秒 |
| `settle_sec` | 0.2 | 0.2–2 | 仅初始标定阶段松手后的等待，秒 |

这些是实验参数，不保证在默认预算内完成六面扫描。控制器先分别标定横向和纵向输入的旋转轴及每像素转角，随后以缺格的可读性和实际新增证据规划补扫，并锁定可执行的两轴姿态路线。远处允许较长拖动，接近目标时缩短；流式控制使用初始两轴标定响应和最新几何反馈。六面完成仍由格子证据判断，正常目标为50秒，60秒为包含特殊情况的硬预算。

## 输出位置与内容

每次运行独立保存到仓库下 `logs/deep_dive_scan/<run_id>/`：

- `report.html`：可离线打开的人工对比报告，包括六面展开图、目标位置、未知或冲突格以及证据链接。
- `layout.json`：可供后续计算读取的结构化结果，包括状态、格子信息、目标位置、观察来源和动作轨迹。
- `frames/0000.png` 等：按观察顺序保存的原始客户区截图。
- `frames/0000_overlay.png` 等：执行布局识别后的叠加图，可与原帧对照格子编号和目标归属。提前被业务门禁拦截的帧可能没有叠加图。
- `cells/U_0_0.png` 等：逐格表面透视裁切，直接展示在报告展开图中；浮空目标仍需结合原截图核对。
- `reset_before_0.png`、`reset_before_1.png`：初始化时用于确认重置控件的截图；初始化过早失败时可能不存在。

每格的 `evidence` 记录来源帧编号及可用的 `frame_path`、`overlay_path`。这些相对路径以本次输出目录为基准。报告生成发生异常时，任务仍尝试保存 `layout.json`，并在返回值中说明报告错误。

格子信息分为两层：目标占用与节点表面图标。玩家、奇点和灵感互斥；一格最多属于其中一种。已确认有目标的格子，其下方图标记为 `not_required_target`，无需识别。没有看清的格子保持未知，不自动当成无目标或普通节点。

## 坐标与完成状态

采用本次扫描局部坐标 `scan_local`，六个面编号为 `U / R / F / D / L / B`，每面 `row`、`col` 都从 **0 到 2**。例如 `F / r1 / c2` 表示本次扫描 F 面的第 2 行、第 3 列。背面和底面的方向也有固定定义，应通过报告及叠加图核对，不要按屏幕左右自行推断。

重置视角与玩家所在面有关，因此不同扫描中的同一个面字母不保证代表相同的游戏世界面。跨扫描或跨回合使用结果前，需要另行建立坐标对应关系。

只有返回 `status=completed`、`success=true` 且 `layout_complete=true` 才表示扫描器判定本次布局完整。仍需通过人工对比确认识别质量。`partial` 表示预算内未完成；`blocked` 表示初始化、跟踪、业务门禁等条件阻止继续；`cancelled` 表示取消。后三种都保留已有结果，但不得作为完整布局输入后续规划。

## 人工检查与反馈

重点对照以下内容：

1. 六面是否重复、遗漏或串面，面内行列是否翻转，侧壁是否被误当成节点表面。
2. 玩家、奇点和每个灵感是否归属于正确格子，浮空和发光特效是否造成邻格误判。
3. 无目标格的图标是否正确，目标覆盖格是否标为无需识别，遮住邻格的特效是否造成漏识别。
4. 未知、冲突和停止原因是否与截图相符，是否出现尚未看清就声称完整的情况。

反馈时请保留本次整个输出目录，至少提供 `report.html`、`layout.json` 及相关原帧、叠加图。指出错误的面、行、列和截图编号，并说明游戏中的正确目标或图标；这些证据可用于区分姿态跟踪、格子对应、目标归属和图标分类的问题。

## 连续拖动与持续识别

最新版本将三条工作流解耦：

- 输入协程约每16ms发送一次短鼠标位移，持续按住；根据新视觉快照调整方向与速度，到达安全屏幕边界后重新选起点。
- WGC后台持续取帧，独立视觉线程通过`capture_stream_frame`原子读取最新图像、generation与到达时间。没有待处理旧帧队列；处理中错过的帧计入dropped_frames。该入口不持有跨鼠标移动的operation lock，也不触发窗口恢复/重建。
- 原图和同帧叠加图交给独立PNG线程，队列上限16；写盘故障或队列耗尽会明确终止，避免无界内存积压。

LayoutScanner只由视觉线程持有，控制端读取深复制快照。方向预测补偿捕获后已发送的鼠标位移，但观察视角是否到达必须以实际识别姿态判定。两轴响应先实测标定，流式阶段固定该基准，避免把尚在移动时的半段角度错误除以整段距离。

输入速度取决于剩余角度和实测视觉处理节奏，最高450px/s，每个新快照之后累计最多发送50px且不超过该次建议距离。反馈年龄超过350ms暂停位移，持续缺失则退出；跟踪失效/界面改变立即停止。取消和结束时先结束输入并释放左键，再等待视觉和写盘线程退出，最后生成报告。

旧版“每70px停下等识别”的112秒记录保留作为历史基线，不代表新版性能。新模式报告额外包含streaming统计，以及每帧处理耗时、跳帧数、每次按住期间的反馈与输入tick数量。

## 快慢视觉分离与抗抖控制

当前扫描由输入协程、几何跟踪线程、语义线程和写盘线程组成。几何路径不再逐帧做目标检测；语义通过容量1的最新帧槽接收RGB、冻结姿态、frame_id和generation。高频姿态与低频布局结果分别发布，控制器不能用处理完成时的新姿态解释旧截图。普通目标为50秒，最大60秒预算中预留约1秒用于收尾和报告；返回值`total_elapsed_sec`包含报告生成。

语义在冻结图像上用图标中心作小幅几何校正，以`source_epoch`与右乘体坐标修正发布。跟踪线程只应用匹配epoch的修正，并重新建立特征射线；迟到的修正丢弃。低锚补充路径要求至少4个已确认且当前图标一致的中心、宽空间分布及严格残差改善，未知图标路径仍要求7个中心；没有降低格子占用/图标的多视角确认门槛。

CellScanPolicy按具体缺格投影评分，包含界面遮挡、浮空目标走廊与画面内倾斜方向；失败视点按实际未新增证据记录负反馈，避免一直重试同一区域。先规划两个可执行旋转轴的路线，再用实际观测决定到达，外推姿态仅用于控制。
