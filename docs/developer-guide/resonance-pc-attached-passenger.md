# 自由货运附加客运

货运任务和试算新增 `auto_passenger`（默认 `false`）及 `passenger_options`。
只有 `trade_mode: free` 支持附加客运；固定线路的直接调用会在操作游戏前拒绝。
附加规划不进入货运求解器，不更改货运路线、货物、用书、协商、疲劳预算或拖车安排。

## 输入

开启时必须填写当前货运编组实际可用的 `seat_capacity`。示例：

```json
{
  "auto_passenger": true,
  "passenger_options": {
    "seat_capacity": 64,
    "flyer_target": 0,
    "transport_level": 100,
    "seat_level": 5,
    "scores": {
      "comfort": 42000,
      "foodScores": 7000,
      "playScores": 7000,
      "petScores": 7000,
      "fishScores": 7000,
      "plantScores": 7000,
      "medicalScores": 7000
    },
    "furniture_bonus_bps": 0,
    "cleanliness_bps": 10000,
    "news": "none"
  }
}
```

百分比内部使用万分比：10000 为 100%，500 为 5%；GUI 直接显示百分比。
当前新闻仅支持 `none`，不自动识别新闻、不计角色、车皮、加印及特殊城市投资收入。
七项评分默认是 SSS 参考值，不表示游戏评分极限。

`flyer_target` 非零时直接采用输入值；为零时按 UTC+8、05:00 开始的服务器日计算，
工作日为 `50 + transport_level`，周末为 `100 + transport_level`。运行中不重置目标。
该数量是停止新揽客的目标，不是派发硬上限。每次点击最大，最后一整车可能大幅超出目标。

## 规划与执行

候选是货运站点序列中的连续区间，可以跨过中间站；同一目的地只取其第一次后续到站。
每批整批上、整批下，不补客、不分批下客。动态规划依次比较未完成目标数量、预计收入、
揽客次数和访问序号。预览没有真实库存，假定库存等于传单目标，并在结果记录此假设。

运行开始仅读取一次真实库存；每次揽客前沿用已确认库存，不重复 OCR，派发后读取
剩余传单作为下一次的库存。首次库存只截传单栏 `[930,10,155,60]`，不包含客舱人数。
在货运交易和恢复之后、行驶之前揽客；满载退券后的库存差是实际消耗。
附加客运不识别启动时已有乘客、实际乘客人数或实际座位数，按用户预设和本次运行中
记录的整批目的地执行，不做空舱验证。到目的站后先结算乘客，再运行投资、回收、恢复、交易
或终点卖货。中间站保留当前批次。拖车和普通行驶均使用货运原有旅行路径。

结清一批后按真实库存重新分配后续客运，不修改货运路线。目标达到、库存不足一次派发
或货运路线结束时停止新揽客。路线机会不足属于正常部分完成，不额外跑车。

旧独立客运仍可同时启用。开启附加客运的工作流按用户顺序独立执行两项，不进入旧联合
商贸的疲劳预算重分配；关闭附加客运时保留原有联合行为。旧入口同样沿用上次揽客后的
余额，独立任务第一次揽客才读取库存；其原有新招募人数展示保留，不读取启动时已有乘客。

## 估算边界

版本化数值目录来自国服原生配置，并记录来源指纹；运行不读取游戏安装目录。
目录重建工具为 `tools/build_passenger_commerce_model.py`。

- 距离使用原生铁路图的最短站点距离，票款使用座位基础价及距离比例。
- 每10张为一次招募、范围中点为平均人数，是尚未验证的建模假设。
- 满载预计消耗向上取整到10张；每次使用最大派发，不把最后一车裁到剩余目标。
- 消费按乘客及标签权重、评分分段曲线、最高评分档位和家具平均加成估算。
- 不模拟车厢分配、拥挤或空座暴击；清洁度对各收益分项的作用范围也只是估算。
- 不从满载结果反推每张真实招客量，避免满座截断和退券造成偏差。

结果中的 `passenger` 单独保存计划、累计实际消耗、库存、批次、未结清目的地及预计收入。
实际结算不识别票款、额外收入、总收益或垃圾产出，不做结算页全图 OCR。
共享动作同时用于旧独立客运，两种入口均只确认结算弹窗出现、关闭及主界面恢复。
兼容的实际收益字段保持 `null`，并标记 `revenue_reading_enabled=false`；界面不显示
已结算收益未知提示。规划预计收入不受影响，也不改写货运预计利润。

## 目的地背景与徽标识别

派发目的地选择不使用 OCR，也不回退到 OCR。规划城市名或配置别名映射到固定城市键，
在列表区域 `[540,75,710,500]` 匹配该城市190×112背景加徽标矩形，不使用蒙版。
21城模板由原生 `HomeStationFactory.leafletMap` 背景、普通态覆盖层和 `cityMapIconPath`
徽标合成，裁掉新闻角标、边框及标题。构建工具为 `tools/build_passenger_destination_templates.py`，
原生提取依赖仅用于离线构建，不进入运行流程。
匹配使用灰度 `TM_CCOEFF_NORMED`、无预处理、阈值0.80；连续两次完整模板命中的
中心偏差不超过3像素才点击。先排除非有限分数再排名，全部无效时停止。

列表先向下搜索，再向上搜索，最多12轮；用缩小灰度图的平均差异判断列表边界。
上下拖动距离均为230像素（原345像素的2/3），保留原起点，仅缩短终点。
拖动到终点后保持按住鼠标、位置不动0.5秒再松开，之后等待0.5秒再观察。
截图失败或匹配技术异常不视作列表到底；未匹配到目标时不提交派发。
三张真实截图回放覆盖10种完整可见城市：完整卡片最低0.8429、缺席城市最高0.5343，
被裁切卡片最高0.7232；普通态模板也能匹配截图中的选中卡片。尚不代表所有城市实机验收。

乘客结算成功还要求弹窗有效消失和主界面模板连续确认，不额外依赖“访问城市”文字 OCR。
主界面尚未确认时，才识别并关闭已知客运升级弹窗，再等待主界面稳定。

## 派发后余额识别

余额从“传单揽客成功”页读取。每次读取前通过成功模板确认当前界面，
然后直接截取固定区域 `[256,134,56,34]`，不做标签定位或结果页全图 OCR。
坐标基于1280×720客户区，不包含窗口标题栏。旧独立客运为兼容人数、座位读取，
仅在其默认人数读取模式下保留结果页全图 OCR；余额同样使用模板确认和固定区域。

原生数字控件固定居中，不能为了排除图标持续右移左边界，否则可能裁掉三位数。
本区域保留完整数字宽度，再依据原生深灰文字颜色过滤蓝黄图标，去除小于8像素高
或面积小于8像素的碎点。预处理只用于此余额字段，不修改全局 OCR 配置。
连续两次只含一个有效数字的结果相同，且不超过已读库存上限时才确认；
空白、异常图片、越界和不一致均保持未知，由原有重试及提交后停止逻辑处理。
当前局部布局的校准范围为0～999。

2026-11-03 ROI校准：3张真实截图（385、405、415）的75次区域偏移回放正确；
0～999在原生字体36、40两档字号下的2000个合成样本正确；只有图标的对照不产生余额。
固定区域方案另外回放真实成功模板及截图，确认数字 OCR 只接收56×34小图。
以上为离线验证，不是新的实机派发或完整自动流程验收。

## 故障和验收

提交前仅明确无消耗的业务失败可在确认主界面后跳过；提交后结果未知必须停止，保留
可能载客的目的地。取消不会重试派发。结算失败保留已完成行驶的证据，阻止后续交易。
启动不检测已有乘客，以用户预设为准；不提供异常后的自动断点续跑。

自动化用例覆盖规划、余额识别、运行接线、取消和 GUI。所有检查从仓库根目录执行，
临时产物放在 `.pytest_tmp`。跨站交易留客、载客拖车及全部异常路径仍需实机覆盖。
