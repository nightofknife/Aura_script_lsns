## 使用入口

在 GUI 的识海深潜面板选择“关卡内自动运行”。游戏客户区须为 1280×720，开始画面须是稳定玩家棋盘或位面间隙。默认“只追奇点”，也可选“灵感收益优先”；独立回合安全上限默认为 100，可设 1–100。复用现有取消按钮。

任务为 `consciousness_deep_dive_planned_run_pc`，采用 `initialize → advance → finish`。任务参数还可设置扫描预算（默认 60 秒）和规划预算（默认 30 秒）。规划始终使用当前位面真实剩余回合。

间隙正常时继续下潜；不足五名可战斗队员时保存状态并暂停，用户整备后可从间隙重新启动。最终结算需标题与布局证据及两次稳定确认；成功、失败、无法区分胜败分别记录，均不点击结算按钮。

## 已接入的循环

1. 每个新玩家回合从重置视角完整扫描六面；必须确认唯一玩家、奇点、54 格布局及最新玩家页面。扫描中覆盖页面会中断并交回调度器。
2. `plan_current_state` 使用当前扫描坐标和真实剩余移动／旋转额度，复用两种策略的完整及剩余动作求解。旧扫描坐标和旧方案失效。
3. 完整扫描结束后点击“重置视角”，回到普通宽视图；两帧稳定三面注册并确认玩家对应后才进入移动或旋转模式。移动放大后重新拟合镜头及顶面投影，旋转模式核对当帧三面及箭头。三面对应至少每面两个有效图案、总计七个锚点；被遮挡的侧面不会伪造为移动视图的匹配证据。该跨视图调整已获用户同意，并已成功执行一次实际移动。
4. 移动按逻辑目标绑定青色格内安全点；输入前重新建立三面映射。旋转以完整 54 格置换绑定箭头，预览匹配才确认，错误预览撤销并核对恢复，最多探测四个箭头。
5. 节点、奖励、战斗各保留来源与恢复阶段。移动额度和节点完成分开记录。任一自身动作结束后仍有额度，首版均重新完整扫描并规划剩余动作；额度耗尽则等待实际奇点阶段。
6. 奇点行动结束、新位面加载后重新扫描，不依赖奇点动作记录。普通战斗胜利不能结束位面；奇点战胜利后仍需实际间隙、新位面或最终结算。

扫描阶段独占输入并排空工作线程；其他推进最多请求一个点击。取消或阻塞时保存状态，释放本任务可能持有的鼠标并排空已启动工作，不依赖 `finish` 一定执行。

剩余回合数只使用客户端原生字形生成的 0–30 数字模板，缺失或歧义时保持未知，不调用 OCR 补填。位面优先识别图标；移动／旋转额度及灵感进度优先匹配数字与斜线模板。只有必要字段或未知页面无法由模板确认时才使用对应区域的 OCR，已确认的战斗、奖励、事件和结算页面跳过 OCR。

## 会话与证据

结果位于仓库 `logs/deep_dive_planned_run/<session_id>/`：

- `session.json`：位面、实际额度、扫描／地图／镜头版本、布局、待确认动作、事件上下文、收益账本及停止原因。
- `scans/`、`plans/`：每次完整扫描与相应方案。
- `operations/<action_id>/action.json`：目标、三面匹配、旋转预览及确认依据。
- `frames/`、`events.jsonl`、`report.md`：输入前与终止截图、事件记录和最终摘要。

`terminal_reached` 表示已经到达结算；`game_success` 表示游戏胜败，未知时为 `null`。收益账本只采用节点结束后或稳定玩家棋盘的地图灵感 HUD 进度，不按奖励点击数入账，也不把奇点战后的旧位面清空计数记作玩家拾取。

## 当前限制及后续验收

- 支持 3×3、每回合一格同面相邻移动和一次层转。额外额度、明确非邻接移动候选、未知节点入口、无法确认的 HUD 或规则暂停。没有可观测证据的隐藏效果仍无法建模。
- 玩家躯干／底座只提供寻视线索，不能独立确认占格。扫描需多角度证据；玩家未确认时不会规划。
- 客户端没有独立选中格标记。移动采用新鲜目标绑定、节点类型、实际额度及后续完整扫描确认，不伪造标记证据。
- 页面资源来自本机客户端；三面阈值、相机先验及备用 OCR 区域仍需覆盖更多场景的实机校准。几何搜索每帧有三秒预算，搜索或证据不足时不会选择输入。
- 尚无确认的战败专用视觉资源；未知战斗画面有界等待后暂停并保留截图。
- 本次新扫描无法对齐前次灵感身份时，不猜测单枚灵感的消失原因；规划使用当前自由灵感集合和已确认 HUD 收集基线。

后续获明确验证授权后，按[完整设计](resonance-pc-deep-dive-planned-run-design.md)中的验收场景检查搬运玩家、三面消歧、HUD 遮挡、四箭头预览撤销、半回合额度、事件来源、位面切换、结算停止及取消清理。
