## 原因与调整

首次预检剖析记录见 [cProfile 原始记录](../../.pytest_tmp/template-collection-followup-20261022-573f22d1/preflight-profile-before.txt)：20 次预检的 0.181 秒剖析耗时中，`Path.is_relative_to()` 累计占 0.095 秒；目录 resolve 约 0.020 秒，stat 约 0.009 秒。剖析含观测开销，用来归因，不当作提速比例。

Windows pathlib 每次完整边界判断会遍历父链，反复构造和规范大小写。现将规范父目录的边界判定放入当前观察作用域，91 个普通文件由逐文件检查父链改为 7 个父目录各判一次。普通子文件继承已确认的目录边界；`..`、根目录本身、非普通名称、目录外父路径及叶文件重解析点保留完整检查。父目录在根外时不直接拒绝，避免将原来的目录读取错误改成越界错误。

另外以两个各限 512 项的缓存复用纯词法 Path 对象，键使用精确路径字符串以保留异常中的大小写与拼写。缓存不保存 stat、目录解析结果或新鲜度判定；每次新观察继续 resolve 目录、检查文件版本及链接，图片仍按原来的完整版本键更新。同观察模板快照规则、ROI、算法、阈值、调用顺序及返回构造保持不变。

- **50 项 pytest 全部通过，无跳过**，包含两个真实 Windows junction 场景：子目录及计划根本身重定向、同帧固定、下帧更新与目录边界。[pytest 结果](../../.pytest_tmp/template-collection-followup-20261022-573f22d1/collection/pytest.xml)

- **76 组扩展路径差分通过**，对照上轮已验收 matcher `0202596c…`，精确比较像素、灰度、标准差及异常类型、消息、args、errno、winerror、filename。覆盖绝对路径、根目录、`..`、NUL、ADS、尾点/空格、非法类型、PathLike、更新/删除/重建、跨帧和模拟文件/目录链接。[路径差分](../../.pytest_tmp/template-collection-followup-20261022-573f22d1/path_semantics_differential.json)

夹具另修复两处不确定性：新增 junction 参数化场景改用每例唯一外部目录；原有版本更新测试为等尺寸写入显式推进 mtime，避免 Windows 同一时间戳 tick 内写入无法形成可观察版本变化。原断言保留，产品版本键规则未改。首次失败报告分别保存在 `collection/pytest-junction-fixture-first.xml`、`collection/pytest-same-tick-write-first.xml`。

## 三版本配对耗时

同一串行窗口比较：`original` 为最初优化前快照，`last_validated` 为上轮已验收实现，`current` 为本轮最终实现。预检与单独房间各 15 轮，其余控制场景各 7 轮；每轮旋转、交替三版本执行顺序。冷态清应用缓存，热态在清缓存后先运行一次；均未清 OS 文件缓存。OpenCV 线程数记录为 32。

真实 catalog 图片构造确定性 1280×720 BGR 客户端，另包含两张已有车间截图；素材及输入构造在计时外。单位 ms，为完整工作负载中位数；“降低”为相对上轮版本，负号表示变慢。“更快轮数”统计 current 小于 last_validated 的配对轮数。极小的 catalog 控制项不作百分比收益结论。原始样本、P95、IQR、执行顺序和源码哈希见 [最终计时 JSON](../../.pytest_tmp/template-collection-followup-20261022-573f22d1/collection/final-benchmark.json)。

### 单独房间的阶段归因

计时结束后另外运行 cProfile，各版本 8 次 physical batch；下列总计及累计时间包含剖析开销，`_asset` 内已包含路径处理，不能重复相加，也不能作为正常速度比例。完整文本和结构化记录见 [阶段归因](../../.pytest_tmp/template-collection-followup-20261022-573f22d1/collection/physical-attribution.json)。

| 版本 | 剖析总计 ms | matchTemplate 累计 ms | _asset 累计 ms |
| --- | ---: | ---: | ---: |
| original | 265.812 | 247.319 | 0.000 |
| last_validated | 344.799 | 267.959 | 58.374 |
| current | 291.663 | 241.342 | 35.177 |

本轮剖析中匹配核约占总计的 83%，路径加载约占 12%；路径加载内 resolve 又是主要剩余项。原始实现命中永久资产缓存时不进入 `_asset` 函数，因此跳过了这些新鲜度与目录链接检查。这解释了路径优化后的单独房间仍未追平原始速度；这些比例只描述剖析样本。

单独房间的完整耗时不能仅由路径优化推算；以同窗配对数据判断，差异小于波动时不宣称稳定提速。匹配核及后处理的进一步实验由另一对话独立维护，本轮不接入其候选。

第一步仅共享 containment 时的 7 轮中间数据另存 [中间计时](../../.pytest_tmp/template-collection-followup-20261022-573f22d1/collection/benchmark-containment-only.json)，其中预检 3.7393→2.7581 ms，而房间 56.8111→56.3192 ms，未据此宣称房间稳定提升。跨轮绝对值受机器状态影响，应使用最终三版本同窗数据。

## 重放

全部从仓库根目录执行，使用仓库 `.venv/Scripts/python.exe`。包装器设置仓库内 TEMP/TMP/TMPDIR、日志、pytest 临时目录和缓存；不使用系统临时目录。

- `.pytest_tmp/template-collection-followup-20261022-573f22d1/collection/run_collection.ps1 -Mode pytest` 或 `-Mode differential`。
- 路径差分：`path_semantics_differential.py`，会核对冻结版本哈希并输出 JSON/JUnit。
- 串行计时：`collection/final_benchmark.py`；预先将 TEMP/TMP/TMPDIR 指向本目录 `temp/`，设置 `PYTHONDONTWRITEBYTECODE=1`、`AURA_VISION_TIMING_SAMPLE_EVERY=0`、`AURA_LOG_ROOT` 为本目录下路径。

以上均为离线测量，不含真实截图接口、动画、输入、等待或整项任务耗时；没有修改深潜专用代码或素材。
