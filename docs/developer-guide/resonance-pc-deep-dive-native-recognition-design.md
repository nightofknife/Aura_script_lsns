## 1. 决策

采用 **原生资源几何约束下的整体姿态估计 → 格子投影 → 图案读取 → 实体归属**。

最终仅保留这一套深潜识别方案。旧识别器只可作为开发期离线对照，新方案验收后整体替换旧识别入口与依赖；不提供旧/新算法切换，不设计自动回退。识别不确定、模型不匹配或证据不足时返回unknown/partial或停止。姿态多解和原生cellModel变体是同一模型内的候选，不是第二套识别器。

首个交付只做离线几何验证，不接游戏输入。识别目标不再是“把截图拟合到四张标准图”，而是“这张图是否能由已核实的客户端模型、相机模式和某个魔方整体姿态解释”。

不再将亮色图案的连通域中心作为格子坐标锚点；不再分别用自由仿射变换拟合各面；不再用这些拟合的形状误差冒充物理旋转角。暂不将训练四角检测网络确定为前置条件：先利用游戏已经提供的模型、挂点、坐标和相机约束。

“只估计整体姿态”是需要验证的受限模型：只有普通棋盘、根与子对象动画已结束、格子变换落在已验证槽位集合时才成立。模型不匹配必须拒绝，不允许靠逐格自由偏移把错误模型拟合成成功。

## 2. 当前客户端的实际证据

原件：`雷索纳斯_Data/Patch/Script/UICubeRogueMain/`。6 个原始 Lua 文件 SHA256 与本机数据仓库的完整字节码解码记录一致；对应规范化字节码与桌面旧分析缓存一致。本轮核验记录：`.pytest_tmp/deep-dive-native-redesign-20261022/native-evidence.json`。

解码记录保存指令、常量、原 Lua 行号和函数原型，并不等于恢复了原源码。复杂反编译条件有错误；下述直线赋值、调用和 DragHandle 关键运算已据相符版本的字节码/反汇编核对。

- 三阶 `Rubik` 预制体有54格，槽位间距为2.4；例如 `Cube(1,1,1)` 局部位置为 `(-2.4,4.8,-2.4)`，其 rolePos 局部 Z 偏移约 `-0.1949129`。这些是特定层级的局部量，不能跳过父链直接投影。

- 已提取当前 `N_01…N_06/Empty` 七类模型的子节点变换、mesh和UV；每类都有122顶点外壳，范围约±1.035～1.042，可构成有限结构候选族。共同轮廓在实际材质/动画下是否足够稳定仍需原图验证。
- `N_01/Empty` 的真实Icon是四顶点面，在grid-root下Z约0.933826，叠加rolePos偏移后距槽位原点约0.738914；UV左右方向反转。`N_05/N_06` 的Icon深度约0.946667/0.948304，不能将不同类型一律当作严格共面。详见审计的 `cell_mesh_geometry.json`。
- 普通相机配置为局部位置 `(-50,41.5,50)`、X旋转29.6、FOV12；移动模式 Y46/FOV8。场景还包含相机父级旋转，不能把上述局部量当世界外参。
- 已辨明场景Main Camera是透视、全viewport、零lens shift；其父级有Y轴180°旋转，场景另有FOV60的UI Camera。最终外参仍须组合父链及Controller运行时赋值；不能挑第一台Camera，也不能将资源初值直接等同截图时刻的状态。

- 当前 `CubeFactory/CubeRogueFactory` 文件已不同于旧导出版本；本轮重新解码当前安装文件，不沿用旧配置哈希。

## 3. 原生几何包：先把真实模型说明白

离线生成版本化几何包，包含以下数据，并记录每项来源是原生读取、人工标注还是估计，三者不可混写。

1. **槽位链**：整体根、每格、rolePos、动态 grid、Icon 的完整父子变换；保留原生 face/row/col 与扫描局部坐标的显式映射。
2. **可见几何**：各 cellModel 的 mesh 顶点、三角形、法线、UV、子网格、材质绑定；筛出普通状态下确实共用的几何与节点类型变体。
3. **相机链**：父级变换、位置与完整旋转、透视/正交模式、FOV、viewport/aspect、近远裁剪、客户区像素映射。配置只给出的局部量不能当完整标定。
4. **状态条件**：Animator、shader顶点位移、层旋后子对象重排、移动选择相机变化。明确哪些已验证静态，哪些未知而应拒绝。
5. **实体候选模型**：rolePos、相关模型包围体与配置偏移；动画/特效膨胀范围另记，不能只存一个格心点。

必须先证明：存在足够的、不依赖尚未识别图标类别的可见几何来估计姿态。若各 cellModel 没有足够共同结构，则保留有限模型变体联合假设；不能先猜图标类型、据此造格框，再用同一裁图确认猜测。变体组合若无法有效约束，判定此路线前置未通过，而不是退回旧亮中心方案。

不会为每个三角形边都生成图像匹配特征。只使用实际可见外轮廓、硬边、缝隙或确实可见的板边；内部三角剖分线和隐藏边不作为观测。

## 4. 单帧识别算法

### 4.1 几何投影

对任意实际 mesh 点执行完整变换链：

`mesh → Icon/grid → rolePos → cell → cube root → world → camera → viewport/client pixels`。

普通静态状态下固定已经核实的相机与局部几何，优先只求根旋转。不能同时任意调FOV、缩放、平移和各格偏移来追求低残差。确实需要标定的参数在单独标定集求解、冻结，再检验其他帧。

使用透视与深度遮挡计算决定哪些面、格边和Icon像素可见；不能只按法线朝前就把被其他块体或实体遮住的格子认作可见。Unity与图像坐标的手性、相机前向、像素Y向下及矩阵顺序须用已知点单独检查。

### 4.2 多候选整体定位

从静态结构建立多尺度边缘与方向观测，动态实体/明显特效区域降权或标为未知。屏蔽检测器没有发现的区域也不自动等于静态。

由原生模型投影产生粗姿态候选，再联合比较：可见轮廓距离、边方向、跨格/跨面空间分布、遮挡一致性。图库是由三维模型投影生成的候选，不是四张标准截图模板。候选密度和运行耗时需在原型中测量，当前不承诺实时速度。

细化阶段只使用有可信对应的3D结构与2D观测。`solvePnP`可作为有对应点时的求解器，不负责产生对应，也不能消除规则魔方的对称歧义。边对应不明确时保留多解，不能把假设的格子编号当作已验证对应。

所有可见面共享同一个整体姿态；不允许左右两面分别自由变形。优化用一组结构，其他格/面上的结构用于留出检验，避免用拟合自身输入的低误差认证结果。来自同一物理边的多段检测不能重复计票。

### 4.3 独立的质量与歧义输出

输出：`pose_candidates`、支持区域、留出投影误差、模型/相机模式、可见槽位、对称解集合、拒绝原因。误差和候选分差是质量指标，不冒称正确概率。

规则魔方的整体旋转对称性必须显式保留。reset和连续观察可帮助建立扫描局部坐标，但不能仅凭“第2视角”就指定原生D面。不能区分的原生编号不交给需要唯一编号的消费者；若采用整体旋转等价的scan_local坐标，需要独立验证规划和行动映射在该约定下保持一致。

首次初始化可以依赖多帧积累支持；短时丢失后可以保留最后姿态作为候选先验，但旧预测不能作为当前观察，不能触发业务动作。

## 5. 几何成立后再识别内容

### 图案

按实际Icon mesh三角形与UV反采样纹理，输出有效像素遮罩。只有原生数据证明该Icon是单平面四边形时才简化为透视矫正；不要从屏幕图标轮廓反推出板框。

图案识别先复用现有分类器作可比较基线，分别核验几何裁图和分类准确率。原生 `_MainTex` 素材可用作类别字典和数据准备；原生纹理并不等于经过光照、材质、遮挡后的实机外观，不能据资源匹配就声明实机识别正确。

遮挡严重、图案变形或可见像素不足时保留unknown；空格必须有明确图案/占用证据，不把未检出当empty。

### 实体

复用已有实体检测作为候选来源，结合各槽位rolePos与原生偏移投影候选区域。几何只负责提出“可能属于哪些格”，最终归属还要有实际检测证据和跨视角排除竞争。

玩家、奇点、灵感的不同挂载/动画行为分开；不要统一扩大矩形后按最近格心归属。对称面、隐藏面、跨格遮挡没有被消除时保持候选集合。HUD数量只能在其语义前提被核实时参与总量检查，不能代填实体位置。

### 融合

按当前棋盘状态、姿态来源和身份链融合。相邻时间帧不算独立视角；整体观察旋转不会自动改变逻辑内容，真正层旋/移动/敌方行动则使旧内容映射失效。`targets_ready`与完整54格读取继续分开。

## 6. 与当前框架的边界

首个原型是从保存图像读取的纯离线工具，无input/app服务，不调用扫描、重置或游戏业务。数据与结果放在仓库`.pytest_tmp`指定scope，运行时依赖不指向桌面归档。

拟拆分为：原生几何包导出、投影与可见性、整体姿态候选、几何质量检查、Icon采样、实体候选归属、旧layout输出适配。先按实际职责实现内部模块，不为每层新增用户任务或服务单例。

首版不向旧控制器提供伪装的`signed_error_deg`，也不替换当前four_views默认路径。离线识别通过后，先接只观察的shadow模式；控制器以后如何利用可信姿态由单独任务处理。当前96次上限、±20微调与80px粗搜不在本轮修改范围。

保留现有WGC原子帧、取消/资源释放、业务事件处理、规划器及已验证的实体检测能力。现有几何匹配、亮色中心和固定标准视角只保留为对照，不作为新方案的隐式回退成功路径。

## 7. 实施与验收顺序

| 阶段 | 实际交付 | 进入下一步的条件 |
| --- | --- | --- |
| A 原生投影核验 | 几何包、来源清单、模式表、少量真实帧上的投影叠加与逐点误差 | 固定坐标链能解释留出格/面的人工标注；动画/相机模式不匹配被拒绝 |
| B 单帧姿态 | 多候选定位、留出边检验、歧义输出 | 清晰帧定位正确，困难帧可拒绝；没有靠独立面变形或亮中心过门 |
| C 图案裁切 | 带可见性mask的真实UV裁图、逐格标签 | 裁图定位与分类分别通过；不混入侧壁/邻格/实体而报成功 |
| D 跨帧身份与实体 | 一致的scan_local映射、实体候选排除、覆盖记录 | 重复面不计新覆盖，状态变化不沿用旧内容，相关候选未闭合则partial |
| E 观察集成 | 只观察shadow输出、端到端耗时与错误案例 | 独立盘面验收后再讨论替换生产识别及后续拖动控制 |

第一项具体工作是A，不是先训练网络或继续跑整套扫描：

- 从本次119帧选不同姿态与失败类型做开发对照，必须包括115–118帧和第二/第四视角粗搜段。
- 人工先看原图标注实际可见的结构点、边和歧义，不把旧算法quad或新投影作为真值。
- 用一部分结构拟合、另一部分结构检验；如已用同一盘面反复调整模型，这些帧只能算开发数据。
- 从桌面旧记录挑选来源可核实的其他盘面建立独立保留集；按盘面/完整会话划分，相邻帧不得分到训练/验收两边。
- 合成投影可测试坐标变换和遮挡逻辑，但不能代替真实图像验收。

指标至少包括：留出点/边的归一化投影误差及尾部误差、错误身份被接受次数、未知比例、可见性误判、图案裁图污染、实体错误归属、单帧P50/P95耗时。容差依据人工标注不确定性与下游裁切/点击需求在标定集冻结；不在保留集上反复调门。

专门加入：错误相机模式、四/五阶盘面、重置/层旋/入场动画、实体覆盖、单面退化、重复图案/对称姿态、模型版本变化。小样本零错不代表生产稳定。

## 8. 尚未证明、不能承诺的部分

原生资源和逻辑让问题有了明确约束，并不自动证明视觉可解。已拿到资源中的Icon mesh/UV、槽位和相机父链；仍须完成它们与运行时模式/初始化的对应、各cellModel共同可见结构检查、动画/层旋后几何一致性、shader影响、有限视角下对称解可区分性、独立盘面准确率与耗时。

若A无法在固定原生参数下解释留出结构，先调查未覆盖的模型/动画/相机条件；若B缺少稳定图像证据，继续改进这条路线的结构观测与对应环节，不添加独立兜底识别器。任何调整必须说明解决哪种已复现失败，并在独立标注上验证。
