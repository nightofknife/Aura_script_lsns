# 每日任务与活跃奖励收集

用户入口为「独立功能 → 日常奖励收集 → 每日任务奖励」。任务引用是
`tasks:daily_rewards_pc.yaml:collect_daily_mission_rewards_pc`，公开动作为
`resonance_pc.collect_daily_mission_rewards`。同一面板提供独立的「通行证奖励」按钮，
实现说明见 [通行证奖励收集](resonance-pc-battle-pass-rewards.md)。

## 页面与执行顺序

从 1280×720 站场主界面启动。使用现有「启程」模板确认主界面，在同一帧内整体匹配
带红点的任务入口。只有主界面已确认、入口匹配有效且明确未命中时，才返回
`skipped_no_reminder`；未知页面或识别技术错误不当作没有红点。

有红点时进入「每日活跃」。优先点击任意一个黄色「可领取」按钮；确认列表刷新、
可领取按钮消失后，再检查金色礼物。有金色礼物则点击任意一个，必须同时看到
「获得物品」标题和底部退出提示，才确认进入奖励弹层。点击空白处 `(500,500)`，
确认回到每日活跃后，再次检查是否仍有可领取按钮或金色礼物。

确认两类可领取状态均不存在后，点击左上角火车图标。重新确认站场主界面才返回成功。
任务不点击「前往」「未完成」或蓝色礼物，不根据礼包图片推断具体物品与数量。

## 确认、补点及取消

- 每次观察只捕获一帧，页面锚点和按钮都从该帧识别。匹配、目标身份与输入帧的有效性
  复用 `ObservationService`、`PreparedTemplate`、`InteractionService` 和 `OperationScope`。
- 点击前连续两帧确认页面和目标，点击目标中心的容差为 2 像素；不复用前一次点击的帧或坐标。
- 点击后至少等待 1.2 秒，再使用两帧确认目标状态。补点前必须重新确认原页面和当前可操作按钮；
  目标不明时只等待，不在未知页面点击。
- 每次逻辑转场最多三次点击，包括首次点击；确认上一次领取生效后重新出现可领取内容时，
  新领取拥有独立的补点预算，累计次数只用于统计。
  一次转场预算 15 秒，整个任务预算 180 秒，页面循环最多 24 次。
- 取消使用框架停止信号。失败或取消不会盲点返回，也不会输出已完成；异常详情包含最后页面证据、
  所在阶段、点击次数和耗时，由框架现有机制保留失败现场。

## 返回契约

成功结果为 `success=true`、`component=daily_mission`、`returned_to_main=true`。
`status` 是 `collected`、`nothing_to_claim` 或 `skipped_no_reminder`。
`claim_clicks` 是领取阶段实际提交的点击次数，包含补点；`reward_overlays` 是已确认并处理的弹层数，
两者都不是物品数量。`stage_clicks` 提供各阶段次数，`elapsed_ms` 提供本次耗时。

动作失败时抛出带 `code/message/detail` 的 `DailyRewardError`；取消保留框架取消异常。
GUI 只有在框架成功、业务返回成功且已确认主界面时显示完成。

## 素材与实现状态

运行目录是 `templates/rewards/daily/`，目录配置是 `data/meta/daily_reward_templates_pc.json`。
入口、金色礼物和蓝色礼物遮罩使用不透明主体；奖励标题和退出提示使用已经审阅的
「图标矩形＋文字矩形」遮罩。退出提示对截图和模板统一做 `blur` 预处理。
来源、原生重建配方、供图和历史分数见
`plans/resonance_pc/development/template_sources/rewards/daily/README.md`。

素材准备阶段已用用户提供截图进行离线校正；本批任务实现仅静态接入，没有新增或运行测试、
编译、打包、素材回放或实机领取。历史匹配分数不代表整条自动化流程已通过实机验证。
