# 识海深潜视觉反馈实施计划

状态：全部为待实施工作，不代表已经落地。先读[方案](resonance-pc-deep-dive-visual-feedback-plan.md)和[交接](resonance-pc-deep-dive-visual-feedback-handoff.md)。

## 分阶段交付与验收

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| P0 输入与基线 | 当前任务调用图、客户端指纹、素材清单、模型契约、数据划分清单 | 缺失资产明确；可从版本化清单定位输入；不依赖另一台机器的临时目录 |
| P1 离线结构观察 | 视频读取、结构/面跟踪、质量评分、稳定帧判定、丢失检测 | 人工标注片段能检查面对应与漂移；遮挡和模糊帧能拒绝；给出逐段误差与失败样例 |
| P2 控制策略回放 | 无真实输入的控制状态机与日志回放 | 增益突变、旧帧、无响应、过冲、丢失、取消都满足有界动作；不会排队盲转 |
| P3 独立实机观察 | 显式启用的观察专用任务，仅正常重置与受限拖动 | 不改变移动/旋转次数；多帧率及切换过程中可恢复到合格观察姿态；记录实际失败与恢复率 |
| P4 六面与四分类 | 朝向相关 ROI、模型适配、六面 54 格覆盖表、世界坐标映射 | 面身份和行列方向可人工复核；不跨 epoch 融合；目标归属冲突能拒绝；按独立局评估 |
| P5 接入规划 | 稳定地图 → 规划 → 状态变更 → 重新观察 | 无有效地图时不执行规划动作；切换选格模式后重新定位点击坐标；既有流程回归通过 |

P1 的录像验证不证明 P3 的输入控制正确。P3 未通过前，不默认启用自动全图规划。各阶段分别记录“已通过 / 失败 / 未验证”，不能只写一个总完成状态。

## 建议模块边界

以下名称是拟议模块，不是已有文件；实施时结合当前代码结构调整。

- `deep_dive_observation_state`：判断棋盘/模式、管理 epoch、统一停止条件。
- `deep_dive_geometry_tracker`：可见面、结构关键点、跟踪质量、稳定性和姿态关联。
- `deep_dive_feedback_policy`：输入前后观测到下一条有限动作的纯逻辑，便于离线回放。
- `deep_dive_observation_controller`：串行执行、帧时序、超时、取消和鼠标释放。
- `deep_dive_cell_observer`：ROI 与四分类模型契约、候选与拒绝结果。
- `deep_dive_surface_map`：规范面/格坐标、覆盖与跨帧融合。
- 观察专用 task/action：作为独立诊断入口，成功后再供单局流程显式调用。

普通状态门禁与事件业务门禁相互协作，但不要重写已有事件退出规则。既有单局、循环和收尾任务不是尚未完成的占位实现，接入前必须读当前版本。

## 最小数据契约

| 数据 | 必需字段 |
|---|---|
| FrameObservation | frame_id、采集时间、接收时间、截图后端、窗口/ROI 尺寸、epoch、业务模式、结构质量 |
| GeometryObservation | 结构关键点、可见面候选、面身份可信度、表面多边形、姿态/对应关系及是否有效 |
| InputSegment | command_id、epoch、起点、位移、时长、发送/完成时间、后端、取消与释放状态 |
| CellObservation | face/row/col 或未定槽位、表面与裁切区域、分类分数、可见性、质量、frame_id、模型版本 |
| ScanResult | epoch、六面覆盖、玩家/Boss 候选、灵感集合、冲突、停止原因、是否可供规划 |

有的截图后端只能提供接收时间，不能把接收时间冒充游戏渲染时间。P0/P1 必须确认可获得的时序信息，并设计旧帧与重复帧检测。图像完全相同也可能是有效静止画面，不能简单把“相同像素”全判成旧帧。

图像坐标、窗口坐标、输入坐标、规范面坐标必须显式区分；缩放和 ROI 偏移只在明确转换处处理。地图有效性不等于执行坐标仍有效：选格入口会改变镜头，点击前须重新获取当前投影。

候选扫描状态机：

`WAIT_READY → RESET → WAIT_STABLE → OBSERVE → DECIDE → MOVE → WAIT_FRESH → OBSERVE`

覆盖充分后进入 `CONFIRM → COMPLETE`；跟踪失败进入有界 `RECOVER`；状态变化使 epoch 失效；取消/超时进入统一释放与退出。任何路径都不允许绕过输入释放。

## 数据和模型工作

1. 按采集局/连续录像分组划分训练、验证、保留测试，避免邻近帧泄漏。保留反复使用过的历史测试集作为回归集，另建独立评测集。
2. 给结构和目标归属分别标注。格子表面框与浮空 Boss 的实体框不可混用；遮挡、身份不明、不可见独立标记。
3. 明确四分类互斥语义；若存在同格多实体，重新决定多标签或优先级契约。
4. 先恢复并核验历史模型，或重训可复现基线，再评估动态视角。历史标准视角准确率不能代表任意中间角度。
5. 检查模型输入通道、颜色顺序、resize、mask、归一化、类别顺序、拒绝阈值和 ONNX Runtime 版本。不要以文件名猜契约。
6. 记录每类召回/误报/拒绝、每局目标定位成功率、归属错误、覆盖缺失和耗时；模型推理耗时与完整扫描耗时分开统计。

## 控制与实机验证矩阵

- 稳定低/中/高帧率；一次扫描中突然变化帧率；截图或输入延迟。
- 无可见响应、旧帧、重复帧、结构丢失、过冲后反向修正。
- 遮挡、强特效、面近乎侧视、只覆盖五面、对称面身份歧义。
- 扫描中自动复位、事件出现、真实移动/层旋转、选格模式或 FOV 改变。
- 任意阶段取消、超时、窗口边界重定位，保证鼠标释放。
- 不同窗口尺寸/缩放与实际输入后端；分别核对截图和输入坐标。
- 小步被当成点击的风险，必须用实际计数和状态变化验证。

先测出安全的单段位移/时长上限、反馈延迟分布、有效拖动下限、恢复次数和稳定帧要求，再把数值及适用环境写入配置。观察专用任务需产出逐段输入与截图对应记录，以便判断失败来自采集、控制、几何还是分类。
