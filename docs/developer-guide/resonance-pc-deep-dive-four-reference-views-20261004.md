## 新路线的实现边界

1. 将这四张图作为标准视角参考。先明确每图可读面、每格实际四边形、
   行列方向及哪些区域被目标/HUD遮挡，建立四视角到同一六面坐标的映射。
   不沿用旧快慢档拖动距离，也不把未标注的平面投影当真值。
2. 取景模块只检查画面几何：格线方向、表面透视比例、位置/完整性、
   运动是否稳定。按固定顺序小步拖动、每步反馈，接近后缩步。
   不能拿整幅参考图（含变化的图案、玩家及辉光）做一张固定模板到位判定。
   相似的两组侧视不能仅凭外轮廓确定身份；保留从重置开始的顺序和连续反馈。
3. 到位、释放、停稳后保存当前原图，再一次性读取图案及目标模型。
   保留玩家/奇点/灵感浮空完整区域；对应视角的格归属另行验证，不能直接
   以框中心落到哪个表面格作为归属。
4. 四图静态基准先分别量化目标检出、图案类别、格归属与六面覆盖，然后
   才做实机到位和整体识别。旧逐面探索及动态六面重建路线停止继续扩展。

这个方向已经按用户意图记录，自动到位与六面归属尚未实现，不声明可用。

## 竖直拖动到位判定原型

用户进一步确认：四张参考图来自老版本一路从下往上竖直拖动。
本轮研究仅离线，没有恢复实机输入。采用二维固定结构边线定位加有序阶段，
不估计完整3D角度，不再做逐面探索。

源码：research/deep_dive_four_view_arrival.py；人工结构线共46条，存于
research/deep_dive_four_view_line_anchors.json。每图覆盖四个区域，避开图案、
目标与HUD；人工端点只是搜索位置，实际参考基线由原RGB的LSD边段测得。
当前图同样提取实际边段，用边界附近法线灰度轮廓排除平行假边，保留候选
和歧义，不调用目标模型或图案分类器。对线段筛选已向量化，只扫锚点覆盖ROI。

到位候选的研究初值：至少6条有效边且覆盖≥3区域；两方向支撑秩满且条件数
≤20；中位法线距离≤2px、p90≤4px、p90图内边线方向差≤1.5°，整体位置偏移
≤3px。这些不是游戏物理角度容差，也未通过真实近点旋转样本标定。
单帧结果仅geometry_match_candidate，不能直接开始识别。

有序阶段必须由真实reset确认建立：锁定下一目标视角，连续3个不同帧、跨
≥.15秒匹配后要求释放；释放后的两个新帧跨≥.10秒再次匹配，才确认本阶段。
至少两帧有正向的已测结构离开证据后，才允许下一阶段；找不到边不等于已经
离开。重复/旧源撤销连续证据，捕获间隔>1秒禁止猜测补跳，要求重新重置。
当前pure gate只处理frame_id/time；实机接入仍需调用方绑定WGC session和真实
输入来源、确认游戏场景及运动已稳定，不把独立离线帧伪装成连续实机帧。

第1/3、第2/4几何近似对称。四图互测当前均没有误判为到位，但这只说明
这四张截图的局部边结构有所区别，不证明换一套图案/动画后能靠单图确定
面身份。因此保留重置、有序竖直过程和离开证据；反向微调不得回退阶段。

离线结果：四张参考自身均给到位候选，有效边7/6/6/6；12项交叉比较均
unknown；±4/±8像素的16项人工整图竖直平移均没有到位误报。这些平移是
图像扰动，不是游戏角度变化。初版只有两张参考自身通过且不能排除部分
4px整图偏移，已保留summary_initial_v1.json，未遮盖失败。
当前单次查询实测约22–114毫秒（含冷调用差异）；没有目标模型/输入耗时。
9项focused tests通过，包含实际边基线、二维位移、区域支撑、缺边unknown、
先离开再进下一阶段、释放复验、重复源及断档。证据在本轮four_view_arrival。

仍需验证两类事实：变化图案/动画的同姿态截图能否持续匹配；真实竖直旋转
的到位前、到位后和过冲帧能否正确区分。四张静图不能提供局部输入响应方向、
惯性、反馈延迟或最大可用步长。下一实机验证应先连续记录同一竖直路径及各
目标附近的细步上行/下行回调，随后再确定粗步、近点缩步和过冲夹区间。
不能由这次基线测试宣布自动拖动已完成或整体99%验收已通过。
