# 有限范围的地图复用分析

当前运行时在玩家第一项动作确认后无条件清除布局，重新完整扫描；在奇点阶段开始、回合变化、位面变化、扫描打断时也清除布局。最可靠的第一步是减少同一玩家回合两项动作之间的完整扫描，不跨奇点阶段复用。

## 建议首批范围

1. **先实现层旋转后的局部核对。** 已验证目标旋转预览、注册过的确认输入、稳定棋盘和实际额度变化共同证明动作已提交。同位面、同回合、移动额度仍未使用，无事件或敌方阶段。54 格内容采用已有整数置换；外层旋转改变20个内容槽位、中层旋转改变12个内容槽位。玩家、奇点、自由灵感与底图必须一起置换，不更新旧像素框。更新只生成待核对候选，正式地图和操作输入仍不得使用它。
2. 用确认后的新棋盘重新建立视图映射，核对实际玩家所在格、至少3个变化图案及至少3个未变化图案，保留当前预览验证的多面与唯一置换要求。必要时换一处局部视角；看不到、重复图案有歧义、检测到冲突时回退完整扫描。确认动作与视图变化分开计数；旧 `operation_frame`、旧 `wide_reference` 全部作废。
3. **后加入普通一格移动。** 仅同回合的第一项动作，实际移动额度0→1，旋转额度仍0，标准1/1额度，已注册目标与稳定返回棋盘。先限无地图副作用的空白节点；漩涡、未知事件、额度修改、战斗、位面跳转均不复用。玩家旧格与目标格局部复核；旧玩家格在全图扫描时允许不识别底图，移动后必须补读该格，不能填成“已知空白”。灵感减少仅在已知目标格有灵感且HUD实际进度增加1时提交；其他消失不归因为拾取。

## 版本和提交边界

- 保留源扫描证据作为不可修改基线；候选保留来源 `session_key/capture_session`、`plane_epoch/scan_epoch/map_revision`、动作ID、精确置换和待核对项。
- 在动作提交前从同一个源版本导出候选；原子动作提交后，候选针对新的 `map_revision` 做局部验证。重复轮询同一个动作ID不得重复执行置换。版本、游戏会话、位面、回合、模型规则版本变化均拒绝使用旧候选。
- 真正的局部图像证据验证通过之前：`success=false`、`layout_complete=false`、`prediction_only=true`，不得继续规划或进入有向输入事务。已知负例和未知均返回补观察，不推断成功。
- 当前 `directed.rotated_layout` 标记 `prediction_only=true`，但沿用旧 `success/layout_complete`。当前 `prepare_operation` 尚未检查 `prediction_only`，所以接入复用时必须增加正式地图验收/输入门禁，不能直接把这个已有预测函数返回值交给执行器。
- `compact_layout` 会去掉逐格来源和姿态。复用需要另存原始证据链，不能把一次数学置换当成新的独立观测；局部再注册需要有当前图像和唯一逻辑坐标映射。

## 不纳入首批复用

奇点随机移动和层转、奇点吞灵感、战斗触发、回合重置、位面更换、地图副作用事件、漏掉的动画、玩家手工干预、撤销恢复不明均完整失效。规则中的随机分支概率只用于规划，不能拿最高概率分支覆盖实际地图。跨奇点阶段若要复用，应另做完整动作观测或对所有合法分支的唯一视觉消歧。

## 本轮验证范围

`reuse_guard_prototype.py` 是独立纯逻辑原型，未接入生产或游戏输入。13项测试通过，包括层转附件一致、预测不可执行、玩家移动揭露未知底图、版本/回合/位面/敌方/预览/事件/额度拒绝、灵感进度匹配、第二项动作不跨敌方复用。测试证明守卫和候选更新逻辑，没有证明图像复核成功率或实机耗时。

若每个普通回合当前执行“全扫→第一动作→全扫→第二动作→奇点阶段→全扫”，首批复用能省掉第一动作后的那次全扫。实际局部核对开销和可复用占比尚待实机计时，不承诺固定秒数或99%准确率。
