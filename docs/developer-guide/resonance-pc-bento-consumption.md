# PC 吃便当子任务

## 职责

这是一个只执行明确消费清单的子任务。它不选择便当、不计算疲劳预算或恢复下限、不读取开始/结束疲劳，也不按优先级或过期时间改变清单顺序。
吃什么、吃几份、如何排序、是否会过量恢复，由跑商等父任务在调用前决定。
便当库存由读取任务保存到本地；本子任务读取 `user-data/user-info.json`，不在消费前盘点、不在消费后重新扫描验证数量。
开跑前的读取先确认便当柜标题和导航图标，再等待列表内容可识别且画面稳定，向下拖动回到顶部。连续多次拖动不再移动，并确认顶部三个工作餐栏位可识别后，才读取所选库存；只读爱心便当也从顶部开始。这个准备步骤不在本消费子任务中重复执行。

只允许从主界面开始。正常完成后点击火车图标返回主界面。
城市面板、便当柜、确认/评分弹窗或未知页面作为起点时失败且不点击。
不加入“小任务”GUI。已接入货运及组合客货运的货运收尾，父流程负责气泡水和便当规划，见 [货运恢复接入](resonance-pc-freight-recovery-integration.md)。不在客运阶段执行。

## 唯一业务参数

任务引用：`tasks:bento_consumption_pc.yaml:bento_consumption_pc`。
共享 Action：`resonance_pc.consume_bentos`。
唯一业务参数为 `meals`，列表中的每个条目代表一份，按列表顺序执行。

工作餐通过时段标识：

```json
{"kind": "work_meals", "issue_time": "12:00"}
```

爱心便当通过父任务读取到的身份标识：

```json
{"kind": "love_bentos", "role_id": 10000004, "food_id": 83300002, "remaining_days": 1}
```

示例 ID 仅说明结构，不代表当前账号仍持有这份便当。父任务应提供读取结果中的角色ID、菜品ID和剩余天数。
名称、评分、恢复量和点击坐标不由调用方传入；子任务从本地库存与计划目录取得目标信息，只在屏幕上匹配这一目标的位置与页面状态，不识别其余菜品来重建库存。

```yaml
eat_bentos:
  action: aura.run_task
  params:
    task_ref: "tasks:bento_consumption_pc.yaml:bento_consumption_pc"
    inputs:
      meals:
        - kind: work_meals
          issue_time: "12:00"
        - kind: love_bentos
          role_id: 10000004
          food_id: 83300002
          remaining_days: 1
```

- 同一精确身份不能重复出现；当前扫描器按角色、菜品、天数组合去重，不承诺同身份多份的数量语义。
- 空清单只核对主界面后返回 `skipped/empty_request`，不会打开便当柜。
- 无旧参数兼容，不再接受恢复下限、优先级、最大份数或开始疲劳参数。
- `entry_point: false`，无 GUI 页面注册。
- 父任务必须检查返回的业务 `success/status/page_state`，不能只看框架节点成功。

## 执行流程

1. 校验清单结构及重复项、客户端分辨率、所需模板。
2. 读取本地库存并核对所有请求目标；缓存缺失、无效、标记需要刷新或没有指定目标时，在界面操作前失败，不自动启动读取任务。
3. 确认主界面，沿既有路径进入便当柜。左下角个人界面入口先检查目标是否已打开，未打开且仍确认在主界面时才点击；沿用恢复导航点击间隔（当前0.7秒），最多点击3次。补点前再次检查目标，避免延迟打开后又被点回去；未知过渡画面只等待，目标打开后才进入下一步。沿用5秒局部等待上限，取消或识别错误立即停止，不重跑消费清单。
4. 严格按清单顺序定位单个目标，确认选中标记、菜品名称和可用“使用”按钮。爱心便当先检查当前视口；没有目标时回顶后向下查找，找到即使用，不先扫描到底。只匹配指定菜品/角色/天数，不分类识别全屏全部便当。
5. 单份使用、确认（若出现）、等待效果页。连续确认效果页后记录已消费，不读取实际恢复量。
6. 工作餐退出效果页回柜；爱心便当选择指定星级、确定后回柜。确认消费时直接标记本地工作餐槽位已使用或删除对应爱心便当记录，不回顶、不重新盘点。
7. 当前一份所有步骤完成后继续清单下一份，完成清单后返回主界面。

子任务不因低疲劳跳过清单，也不擅自补吃清单外的便当。游戏本身拒绝使用、目标变化或识别不明仍属于执行失败。
工作餐仍按约定36记录基础恢复量；爱心便当按FoodFactory基础值记录，不计算账号加成。评分为菜肉俱全汉堡83300002、焦香水果派83300011一星，其余九种已知菜品五星。

## 数据与结果

本地库存和消费证据通过 `core/persistent_data` 更新 `user-data/user-info.json` 的相关便当字段和 `metadata.bento_consumption`，不写入任何新盘点结果，不读写疲劳数值，不覆盖气泡水等无关字段。
父任务如需消费后的实际疲劳，必须另行刷新，不能把消费前缓存当成消费后结果。

返回：
- `success/status/reason/page_state/requested_count`。
- `consumed_count/completed_count/work_meals_used/love_bentos_used/recovered_fatigue/items`。
- `requires_refresh/failure_stage/error/elapsed_ms`。

`recovered_fatigue` 是已确认消费按固定基础值的合计，不是实际疲劳差。
已确认消费与评分/返回完成分开记录；重复确认不会重复扣减。
任何一份失败则停止，不自动重跑或换目标；部分已消费记录保留。取消后不继续输入，等待实际worker退出。
异常/取消不强制回主界面。缓存中的相关资源若标记 `requires_refresh`，调用方需显式安排读取任务刷新；吃便当任务不会把读本地缓存当成一次刷新来清除标记，也不会从评分页直接启动。
