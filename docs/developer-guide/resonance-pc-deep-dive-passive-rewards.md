# 节点结束后的被动道具奖励

`_deep_dive_node_rewards.py` 在战斗领奖／收尾、商店返回、空白返回、准备旋转期间，优先检查结果展示和追加道具选择；有弹窗就处理，回到魔方后再恢复原阶段。保留原节点状态，不重复提交移动或回合。回生空洞和漩涡继续使用各自的独立流程，分别确认连续不同结果页。

识别复用空白退出提示与已有选择控件，不依赖“恭喜获得”这一种标题。“额外激活”等结果共用关闭逻辑。道具选择按1张唯一、2张左边、3张中间，只检查目标勾选。

结果页面使用卡片／标题区域24×24灰度特征辅助区分不同结果（平均差异大于8），新页面重新确认后处理；同一页至少间隔2秒、最多3次点击。不限制奖励页数，也不按奖励段总时长截断；只在30秒没有进展时停止。无效截图重置稳定计数，未知页面不猜测输入；结算检测仍优先。

关闭奖励后恢复原阶段并清除返回界面的旧稳定计数，不把关闭点击直接视为节点完成。物品溢出替换和未支持选择页面仍停止保留现场。

## 灵感前置结算

补充支持到达节点后、节点主内容前的灵感结算：连续恭喜获得、获得直觉、获得物品展示均点击空白关闭。获得物品的退出提示位置更高，使用独立紧裁提示与获得物品标题联合识别。

战斗准备阶段在奖励结束后恢复等待队伍选择；商店等待商店；回生空洞／漩涡等待实际选项页。前置奖励期间短暂露出的魔方不会被视作节点完成。小玩意儿自身奖励仍按原事件处理，避免误等不存在的选项页。

奖励页数不按固定样例数量限制。获得直觉仅关闭领取展示，不执行道具使用，不主动增加旋转次数。
