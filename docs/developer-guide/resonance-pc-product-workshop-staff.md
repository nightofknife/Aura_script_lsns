# 生产车间补人（PC）

任务：`tasks:fill_product_workshop_staff_pc.yaml:fill_product_workshop_staff_pc`，展示名为“生产车间补人”。起点为普通整顿中心总览，客户区固定为 1280×720；首版入口支持现有导航素材覆盖的 1 号、2 号生产车间。调用时必须传入 `room_name`。

## 已确认流程

1. 复用整顿中心导航打开指定生产车间。
2. 点击“车间编辑”文字上方的蓝色图标。以文字模板定位后向上偏移 50 客户区像素，1280×720 下落点约为 `(1135, 635)`。
3. 点击快速编队。
4. 只识别“一键选中 / 一键取消”按钮，不读取人数。显示一键选中就点击；进入时显示一键取消则直接返回，不点选人、确认或保存。
5. 点击过一键选中时，再点击确认，识别返回编辑页。
6. 点击左上角返回，识别到保存弹窗的确认与取消两个按钮同时出现。
7. 在提示中确认保存应用。
8. 再次点击左上角返回，识别到普通整顿中心总览后结束。

“退出”指第 6 步的左上角返回，不是另加一个关闭人员选择面板的操作。选择确认只修改本地编队；不能把这一步当成已保存。保存提示中的原生按钮文案为“确认 / 取消”，代码用 `apply` 表示确认保存的业务含义。按用户要求，不识别“布局已变更”等提示文字，仅确认与取消按钮同时匹配时判定弹窗出现；只匹配其中一个时停止。另一条无需操作分支则从选择页逐层返回总览，不提交选择或保存。一键取消出现在点击一键选中之后时，仍继续本次确认保存，不能与进入时的一键取消分支混淆。

任务使用游戏自带快速编队候选规则，保留现有人选并补空位，不另实现逐个囚犯选择或排序。客户端候选逻辑包含 Free/InPrepare；不要将这个任务描述成“仅选择完全空闲人员”或保证不会移动其他位置的待岗人员。

## 实现与失败行为

任务 YAML 管理顺序与失败后的跳过；`product_workshop_staff_step` 每次只执行一个步骤。匹配到提示即接受，不要求提示保持多帧，也不依赖保存成功提示一定出现。

补点仅实现在 `product_workshop_staff_pc_actions.py` 的私有 `_click` 中，不修改公共点击方法、共享导航或任务 DAG。每次点击后等待 1 秒再截图；目标状态出现立即继续。只有原页面仍在、原按钮仍能定位时才补点，最多点击 3 次（含首次），每次用新截图重新定位。原按钮消失、页面变化或无法识别时不再补点，只继续等待预期后续页面，最多沿用原有 6 秒识别预算；没有识别到则停止。截图或输入明确失败也立即停止。

返回按钮在下一页仍可能存在，因此先判断目标页面，再判断原页面与按钮，防止重复返回多退一层。保存弹窗关闭后不补保存；一键选中变为一键取消后不再补选人，继续确认保存。原一键选中按钮持续存在时最多尝试 3 次后报 `staff_click_retry_exhausted`，不会继续确认。进入时已显示一键取消的直接退出分支，也只对各层原页面上的返回操作有限补点。

每次尝试记录步骤、按钮、尝试序号、等待时间和等待后的页面；需要补点时额外记录原页面与按钮是否仍在。总览进入房间继续使用共享导航的原有行为，不增加入口补点。

2026-10-17 按用户进一步简化：移除编辑页人数、选择页分数与人数一致性检查，仅凭完整按钮和页面模板继续流程；不调用数字识别、OCR 服务或游戏运行时接口。两种蓝色按钮共用大部分背景，按两者的最佳匹配分和至少 0.01 的差距确定具体文字；分数含糊则停止，不点一键取消。

结果区分：

- `unchanged`：进入时显示一键取消，未修改、未确认或保存，并已返回总览。
- `submitted`：已点击一键选中、确认并提交保存，返回总览。`success=true` 表示这次 UI 提交闭环完成，不表示人数已满或服务器保存结果已复核。
- `failed`：未知页面、按钮含糊或不符合预期、确认保存页面变化未确认，或返回总览未确认。后续写入步骤跳过，保留页面与点击证据。

结果输出包括 `selection_action`（`selected` / `unchanged`）、`applied`、`returned_to_overview`、`page_after` 与逐步骤证据，不输出人数字段。原生保存回调发送异步请求后立即返回，既定流程没有额外重开编辑页复核；因此 `save_verified=false`。框架节点成功不代表业务成功。

## 模板来源与验证边界

最初模板来自游戏原生素材、字体和预制体布局合成。2026-10-17 按用户提供的两张裁片，将标题与快速编队升级为包含图标、文字、背景的完整特征块，去掉裁片外层纯黑边。快速编队使用 124×35 图块；车间标题使用 203×61 图块，包含左侧图标、车间名和下方机型。标题中的编号另在同一图块内比较匹配分与差距，避免共用图标造成 1、2 号误认；不再保存单独的 30×18 标题模板。原生合成版本也保持完整图块，作为带来源记录的变体支持原生场景回放。

素材脚本为 `tools/build_product_workshop_staff_templates.py`，版本化目录为 `templates/workshop/staffing/editor/`，来源、布局和示例场景记录在 `data/meta/product_workshop_staff_templates_pc.json`。`--refresh-feature-blocks` 可只从已保存场景与用户裁片重建这几个完整图块，无需再次提取游戏资产。生产车间入口继续使用已有真实截图模板。运行时只读取随计划打包的模板，不要求本地安装目录存在或读取游戏数据。

一键选中、一键取消与确认使用用户给定的按钮图。一键选中与一键取消按白色图标和文字边界保留左右 6、上下 4 像素蓝底余量，模板分别为 110×27、111×26；匹配原生合成场景的变体也同样收紧。每个变体分别记录裁切锚点，点击仍落在按钮中心。已有真实选择页上，一键选中和确认匹配分均约 1.000；一键取消在合成对照场景中验证，不将它当作人数已满的证据。原人数标识、人数区域和数字模板从运行目录索引中移除。

保存弹窗确认与取消使用用户给定的实机裁片，保留图标、文字与左右 6、上下 4 像素背景余量，模板分别为 108×48、101×48。实机布局中两个文字组位于各自按钮中央，原生预制体示例位置不同，各变体分别记录匹配区域及锚点。已有真实保存弹窗上，两者匹配分均约 1.000；点击落点分别约 `(960,505)` 与 `(320,505)`，任务只执行确认保存。提示文案模板从运行索引移除。

主要原生逻辑依据：`UIPrisonEdit` 的 `ShowPrisonerList`、`OneBtnSelect`、`RefreshPrisonerListBottomPanel`、`RefreshTopInfo`、返回保存回调及 `SaveChanges`；`CommonTips.OnPrompt` 与 `UIPromptLuaBehaviour`。复杂反编译条件不能直接视为可靠布尔逻辑；实际操作顺序以用户确认流程为准。

`tests/fixtures/product_workshop_staff/` 中原生预制体场景明确标为合成；`live_room1_entry_20261017.png` 是用户提供的真实入口截图客户区裁片，另有来源与裁切记录。离线图像匹配、模拟输入和真实 DAG 测试只能验证实现与这些素材之间的一致性，不代表模板或保存返回流程已通过实机验收。

2026-10-17 前两次实机进入编辑页后，旧标题和快速编队合成模板未达阈值而停止。更新完整图块后，第三次已打开快速编队选择页，但旧按钮模板与人数区域失败而停止。移除人数检查并更新按钮后，第四次已一键选中、确认并返回到保存弹窗，但旧保存模板失败而停止，未点保存。更新保存模板后，第五次完整执行一键选中、确认、返回触发保存、确认保存与返回总览，结果 `submitted`，结束时无待执行活动。第六次运行使用有限补点实现，7 个实际点击均为 `attempt=1`，约 10.304 秒完成 `submitted` 并返回总览；结束时无待执行活动。这证明该版本正常首次点击路径已在 1 号车间完成 UI 提交闭环，没有实机触发补点，也没有复核服务器持久化结果。漏点后的补点只通过离线场景验证；2 号车间目前只有原生合成场景和编号互斥回归覆盖，没有本轮完整实机流程记录。

集成保留主线的停止保护：每次操作使用可恢复的取消检查上下文，截图后、发送点击前及确认等待中检查停止信号；新增 1 秒等待也每 50 ms 检查停止。取消直接抛出 `CancelledError`，不报告普通失败、不继续补点或后续步骤。本次合并验证采用离线测试，没有新增游戏操作。

一键选中完成后，确认前的新截图必须仍显示一键取消；确认漏点后补点也须保留该状态。若退回一键选中，报告 `staff_selection_button_changed` 并停止，不继续确认、重新选人或保存。
