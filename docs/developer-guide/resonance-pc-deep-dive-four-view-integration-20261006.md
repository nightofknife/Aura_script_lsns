# 四视角扫描接入现有任务的设计

日期：2026-10-06。状态：正在实施；四视角已接入正式扫描和自动运行接口，默认切换及操作实机验收尚未完成。

## 接入决策

保留现有“布局扫描”“关卡内自动运行”和循环任务入口，保留规划器、移动、层旋转、
事件处理及回合状态机。在 `run_layout_scan()` 增加 `scan_route=four_views`，让新的
四视角扫描生产现有布局契约，再由原任务继续运行。

四视角路径固定为：实际重置 → 第一组两个侧面 → 底面 → 第二组两个侧面 → 顶面。
用户已确认：重置后的玩家面就是顶面，第一组侧面就是初始图顶面下方朝镜头的两个面。
这定义的是每次扫描的局部坐标系；玩家移动到其他面后再次重置，新的顶面需重新建立，
不能复用上一次扫描的slot编号或把局部U当客户端永久面ID。

本轮不把研究 broker、磁盘命令文件或 monkeypatch 带进正式任务。正式扫描直接使用
已注入的 app 和实体模型服务，在一次 async 生命周期中独占输入、读取真实新帧，
结束后交回原状态机；取消时释放鼠标、等待正在进行的输入/识别收尾，不关闭共享游戏。

## 现有任务接缝

1. `consciousness_deep_dive_scan_pc_actions.py:1159` 的 `run_layout_scan()` 是共同扫描入口。
   独立扫描 action 输出摘要/HTML/JSON；planned_run 的 `_scan_turn()` 直接消费完整layout。
2. `consciousness_deep_dive_planned_run_pc_actions.py:669` 的 `_scan_turn()` 设置独占输入，
   传入实体服务、HUD灵感上界和进度回调。新路线只需要改变扫描选择和预算。
3. 扫描结束后仍走 `accept_scan → reset_wide → wide_reference → planning`。
   HUD需与扫描开始一致；执行前必须重新取得用于点击的三面联合参考图，不能拿
   扫描结束的第四视角格中心直接点击。
4. `_deep_dive_operation_frame.py`、原 directed input 继续负责坐标注册、操作模式、
   预览和确认，校验 scan_epoch/map_revision/actor_slot/view_epoch。
5. 首次接入保留原来的动作后重扫。移动、层旋转、敌人阶段、新回合/位面变化都使
   旧布局、计划和点击参考失效。局部更新优化留到完整流程稳定后。

GUI当前扫描和自动运行都使用外层timeout=0，由内部管理可取消预算，因此不新增
另一套页面或任务。既有GUI进度事件扩充view_index/view_count、当前阶段和已知格数即可。

## 布局输出与坐标

沿用 `resonance_pc.deep_dive_layout.v1` 和 `coordinate_frame=scan_local`。
规划器面顺序是 `U,R,F,D,L,B`，row/col是0..2，slot=`face_index*9+row*3+col`。
必须使用 `_deep_dive_planner_rules.py` 的 `BASES/cell_to_slot`，54格唯一覆盖、无重复。

拟议局部命名：顶面U、底面D，第一组画面左面F/右面R。另两面用反面拓扑和
竖直路线确定L/B；实施时验证左右与行列变换，不能照抄截图的“左/右”或手工表格行列。
每个局部面需有显式的整数行列变换，旋转/翻转只改变索引，不改变真实格图。

为每次扫描增加坐标元数据：`scan_epoch`、`frame_convention_version`、`reset_player_face=U`、
实际reset证据、四视角身份、六面映射、参考图来源和每格实际quad。
`reset_player_face` 是拟新增字段，目前代码中不存在。

每格保持：`occupant/occupant_status`、`icon_id/node_kind/node_status`、confidence、
实际来源/evidence及独立证据计数。目标格下面的图案允许未知；确认的玩家/奇点/灵感
占用和普通图案的已知程度分别记录。

- 白色破方框 `white_diamond` 对应真实empty。
- 未确认或冲突保持unknown，不能用空节点填充。
- 橙色三眼是图案族，不能擅自唯一解释成某个战斗事件。
- layout_complete、targets_ready和success保持各自意义。

输出继续提供 `player_cell/singularity_cell/inspiration_cells`、six faces、54cells、
known_cells、faces_observed、expected_inspirations、diagnostics及summary.total_elapsed_sec。
外层保持 `{success,status,reason,layout,summary,last_frame}`，失败返回明确未就绪原因。

## 姿态定位与图案读取

当前SIFT模板用本棋盘内的图案作为宽域特征，不能简单复制四张图片到计划data目录
就宣称跨棋盘可用。正式几何定位优先使用格边、面轮廓、三层格结构和长边方向。
保留已验证的主面/双侧面方向反馈及HUD完整性检查；参考几何和图案类别分开存储。

若结构定位还需要局部图像基准，必须在新棋盘扫描时自动建立，不要求人工先给四张图；
图案变化可以帮助当前基准跟踪，但不能作为面身份和到位姿态的唯一依据。
先测试不同棋盘的同姿态、移动后及层旋转后的棋盘，再开放正式默认路径。

到位后保留三张不同generation、同session/scan_epoch的新稳定原图。
对同格至少两张确认同类且零已确认冲突；三个稳定帧只用于时序一致，不伪装成
三个独立视角。分类API不接收expected_icon；GT评分只放测试fixture/离线评估脚本。

## 浮空目标的自动所属格

目标模型读取完整面及外扩区域，普通图案读取真实格面quad；不把目标裁死在格框里。
模型框中心不是格中心：玩家、奇点和灵感都可能离开其承载面。

具体步骤：

1. 在主视角内检测类别/框及实际可见像素，按完整格面生成候选格。
2. 使用目标支撑/脚点线索、面法向外扩后的候选区域及从原生资源核对的偏移范围，
   对候选格打分；不直接选择“框中心落入”的格，也不对所有目标使用同一个固定偏移。
3. 跟踪相邻标准视角中的同一实体，验证同一面/格映射；截图侧边露出的目标只能是
   待解释候选，不能就地算成新的实体。用户确认的四个目标位置做首个回归真值。
4. 同类候选格接近、跨面不确定或某目标缺少第二个真实视角时，只补该面附近的
   小幅偏转图，已可靠的面不重复做完整重扫。
5. 仍存在相关未归属候选时targets_ready=false；不得用HUD总数反推某个格占用。

记录类别置信度和格归属证据分别来自何处。单帧最高置信度只能在一致候选中择优，
不能消除跨格/跨面冲突。

## 接入ready门槛

首版优先保留现有 `_deep_dive_target_readiness.py` 的真实独立证据门：每目标≥2个
实际view group，旧fusion还要求真实姿态分离≥8°；none完整占用证明要求≥3group。
四个不同标准视角是真实观测组；同一姿态的三张稳定截图属于同组。

玩家在第一视角上方和第四主面、奇点在第二主面和第三上方、灵感在相邻面重复出现，
可用于真实跨视角复核，但只有自动格归属可信时才计阳性证据。缺口按需补拍。
当前图像形变角不等于真实物理姿态角，不能用它冒充旧8°门槛；若旧fusion接口不能
消费新证据，须新增明示的four_view证据校验分支并独立验证，不能填假pose/group绕过。

HUD剩余灵感是上界。已经找到上界数量即可关闭清单；少于上界时，只有完整负占用
证据能证明不是漏识别，保留奇点可能吃掉灵感的逻辑。图案empty和目标occupant=none
也不能混为一谈。

当前旧ready还检查最后的glyph_anchor_reason/age，新路径必须用实际当前参考图说明
锚定来源，并维持执行前fresh registration；不能给固定低age或借用旧扫描结果。

## 模块与预算

|拟新增模块|职责|
|---|---|
|`_deep_dive_four_view_control.py`|有序reset/反馈/有界竖直输入/释放复核；灵敏度适配接口仍占位|
|`_deep_dive_four_view_geometry.py`|棋盘无关定位、六面身份/行列变换、实际quad与源关联|
|`_deep_dive_four_view_reader.py`|裁格和纯图案融合；没有人工评分|
|`_deep_dive_four_view_targets.py`|完整区域实体检测、浮空所属格、跨视角去重/冲突|
|`_deep_dive_four_view_scan.py`|一次扫描的编排、layout适配、进度与退出；使用现有app/detector|

保持注入的实体服务，正式模块不import research，模型用计划内data/models。
研究DirectML库仍在 `.pytest_tmp/.../model_dml_env`，接入/打包时改用受管理的依赖目录与
正式配置，并设置worker Python路径；共享app/detector的关闭责任不能转给扫描helper。

用户已暂时取消识别时间目标，但不能没有任务失控保护。新路线拟用300秒可取消保护
预算（可配置），单次有界拖动、每阶段步数/无进展保护仍保留，达标即结束。
它是保护预算，不是性能合格指标。原型仍未测试其他灵敏度，不宣称已适配。

必须一起处理两个任务YAML的default60/max90、scan内MAX_RECOGNITION_SEC及两处钳制、
planned_run两处min(90,budget)。initialize已允许5..900；scan_turn watchdog实际为
max(90,scan_budget+30)，不能误称其永远固定90秒。扫描预算与执行前reset_wide/补格
预算分开记录；旧路线限制保持原语义，新four_views走明确配置。

## 实施顺序与通过条件

1. **纯模块与坐标**：拆出无GT的读取/融合，建立54格双向映射，生成带面名/格号的
   六面报告供用户核对。测试四组身份、D/B/L镜像/转置、跨边邻接及规划器层旋转置换。
2. **只接布局扫描**：新增four_views选项，输出正式layout/HTML/JSON，不执行移动。
   测换棋盘、空/未知、目标偏移和重复露出、HUD变化、错阶段/旧帧、取消后的鼠标释放。
3. **规划预览**：正式targets_readiness通过后交给原planner，只展示下一步和预期旋转，
   校验snapshot/scan_epoch。不得用人工填的目标格通过这一阶段。
4. **操作接入**：先一次移动，再一次层旋转，分别检查模式注册/预览/确认、HUD扣次、
   图案/目标真实变化和动作后重扫；再测事件返回、敌人回合和新位面。
5. **默认切换**：上述流程通过后才让原GUI默认four_views；同步manifest，运行
   package check/validate、Plan Doctor和相关回归；旧探索路线随后成组退出活跃实现。

以上是最初接入设计。当前实现和验收情况见下面的实施记录；最终完成条件仍是实机操作及重扫验证。

## 实施记录

### 已接入的正式路径

`run_layout_scan(scan_route='four_views')` 直接消费注入的 app、原子 WGC 新帧和计划内实体模型服务。
没有导入研究 broker、人工 GT 或外部参考 PNG。几何 JSON 只保存无类别的参考格边和格面坐标；
参考 PNG 路径仅为来源文字，不是运行时文件依赖。本次扫描确认标准位置后才从现场 RGB 建立
局部注册基准，按当前 epoch/session/map revision 检查来源。

扫描保存54个规范格坐标、实际 quad、普通图案读取及目标证据。三张同位置新帧只计一个
视角；每组另外两个经过实际输入和图像偏移核验的补拍位置才计独立组。
隐藏面投影只提供候选，不能产生正占用、负占用或普通图案读取。目标直接确认仍要求
至少两个真实可见组；别名排除要求至少三个真实直接负观测组。

预算按路线区分：four_views 默认保护预算300秒、最多900秒；旧路线仍受90秒上限约束。
planned_run 的执行前重置、三面映射及补读另计保护预算。取消和异常路径排空线程并释放
鼠标，不关闭任务拥有的共享 app/实体模型。GUI已区分目标完成、完整图案完成和部分结果，
离线预览重新核验目标证据后才接受目标布局。

### 重复测试中处理的卡点

- 两面配准须独立拟合后联合检查竖直旋转一致性，不能借用另一面的矩阵。
- 主面宽高比例在正对镜头前后可能同号；局部控制改用实际格面中心相对目标中心的
  上下偏移，且没有完整图案中心支持的侧壁配准不得控制拖动。该量是图像位移角度，
  不宣称为物理旋转角。
- 局部反馈不能把小噪声放大成80像素粗拖动；局部修正有界20像素。反馈失效时先静止
  重新采集，不能沿失效矩阵继续修正。
- 长遮挡后的目标新轨迹不继承旧ID。动画侧边线索只有在真实连续、无竞争轨迹和
  已有几何确认结论一致时才解释，解释不会增加直接正证据。
- 扫描结束后不再额外回到第四视角中心。下一操作阶段本来就需实际重置；最后只用
  第四视角补拍位置的新图验证当前配准，避免无用拖动。

尚未切换GUI默认路线；仍在现有自动运行状态机中验证第一次真实操作及动作后重新扫描。
失败报告、输入记录、原图和来源均保留，没有把blocked/partial改写成实机成功。
