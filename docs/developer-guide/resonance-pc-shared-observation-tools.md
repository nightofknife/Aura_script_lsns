# PC 便当观察、资源校验与等待工具

本批只整理雷索纳斯 PC 包内重复的基础逻辑。公共工具不注册为动作或服务；任务入口、模板目录和识别配置保持现状。深潜及其共用依赖不参与本次整理。

## 工作餐槽位

`_bento_observation.py` 接收已完成匹配的“有餐/空槽”结果，分别应用各自阈值，返回有餐、空槽、两者都命中或两者都未命中。截图范围、匹配方法、灰度参数、错误检查和重试由调用场景保留。

恢复读取仍从同一张便当区域截图裁出三个槽位，一轮完整可信结果即可保存；读取超时保留原有 `assumed_empty` 降级。自动吃便当仍逐槽截图、拒绝非有限分数，要求连续两轮一致，超时失败。消费流程不调用恢复盘点来替代自身观察。

## 稳定帧

公共工具保留原有比较规则：每像素最大通道差大于 15 才算变化，变化像素占比必须小于 1%。连续观察器首帧只建立基线；不稳定时清零，缺页或内容未加载时由调用方重置。

每个场景继续决定何时截图、先等待还是先截图、需要几次连续确认、总时限及错误。恢复读取的内容加载检查、拖动输入确认、回顶证据独立保留。画面静止只证明没有移动，不能单独证明已到顶部。

## 资源校验

`_recovery_assets.py` 提供 JSON 读取、计划内路径解析、指定 flags 的图片读取及 ROI 校验。恢复、爱心便当、消费和气泡水加载器复用这些基础操作；各自保留 schema、尺寸、通道、dtype、mask、阈值、加载顺序及错误策略。

路径在读取图片之前检查所属计划。工具不猜测模板颜色或 mask 用途，也不增加旧路径回退。爱心便当的 `navigation_only` 仍不加载完整识别资源。

## 可取消等待

`_cancellable_wait.py` 通过调用方传入的 sleep、时钟和取消检查工作，保留三种原有时序：

- 交易、旅行和带上下文的改装中心：累计请求的等待片段，每段最多 0.05 秒，保留等待前和每段后的取消检查；异步交易采用相同时长策略。
- 采购书、议价：按单调时钟截止时间等待，把调度开销计入预算，保留原检查顺序。
- 便当消费：在本次操作既有截止时间内等待，保留循环内及结束后的 guard；guard 同时负责取消和消费总时限。

取消异常由各场景生成，交易错误、异步取消和便当业务错误不互换。改装中心没有上下文时仍执行原来的一次 sleep。

回收的等待函数继续保留原实现，它对非法时长的处理顺序与采购书、议价不同；本批不改变它的失败行为或第一批加入的奖励弹窗上限。

## 消费边界与验证

公共工具不点击、不记账、不重试消费。指定餐身份、清单顺序、按钮消失后的重试禁止、效果确认、评分及消费后库存更新仍留在原场景。气泡水的不确定状态锁、一次记账和免费次数保护保持。

回归覆盖真实模板离线回放、加载与回顶、超时降级、连续槽位确认、取消和部分消费。另用本批修改前源码对照资源加载器返回值、异常及加载调用顺序；深潜依赖闭包、配置、模板与原已暂存修改通过哈希检查。离线结果不代表实机消费验收。
