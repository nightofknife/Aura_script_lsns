# 识海深潜灵感收集与奇点追击规划设计

日期：2026-09-30。本文设计在指定剩余回合内收集灵感并与奇点相遇的规划器，接续[全魔方布局识别](resonance-pc-deep-dive-recognition.md)和现有单局移动执行流程。后续已实现只追奇点和灵感收益两种独立规划算法、GUI 与任务入口，见[规划器使用说明](resonance-pc-deep-dive-planner.md)；当前阶段生成离线方案，自动执行和实机验收尚未接入。

核心决定是搜索带有奇点随机分支的行动策略。规划必须同时考虑玩家移动、玩家层旋转、奇点移动和奇点层旋转；每次实际行动后更新地图，再执行对应分支。保证模式要求所有建模的奇点随机结果都能在预算内相遇，在这些可行策略中最大化保证能收集的灵感数量。

后续[第一位面数值计算](resonance-pc-deep-dive-planning-statistics.md)发现：从第一位面初始位置出发，即使只追奇点也没有有限最坏保证。六回合保证模式会返回无保证方案；实际行动需使用明确的概率目标，区分最大化到达概率、全部灵感成功概率和按期成功的灵感收益，不能把接近百分之百的成功率当成绝对保证。

## 需求与优化目标

输入包含当前完整布局、玩家位置、奇点位置、尚未收集的灵感、剩余回合 T，以及本回合已经使用和仍可使用的移动、旋转次数。成功指玩家主动走到奇点格，或奇点主动走到玩家格并触发奇点战斗入口；战斗胜负由既有战斗流程处理。

相遇时刻不得晚于 T 的最后一轮奇点行动。能得到更多灵感但不能按期相遇的路线不属于可行解。多个可行策略按以下顺序比较：

1. 最大化最不利随机分支下，玩家保证拾取的灵感数量。
2. 保证拾取数量相同时，尽早保证与奇点相遇，保留回合余量。
3. 前两项相同时，优先减少未知节点、未支持事件和额外战斗，再按稳定动作顺序选择。

这里的“最多”是所建模规则下的最大保证收益。若需要最大期望收益，可以在所有分支按期相遇这一约束内改用期望值排序，但须提供随机概率模型；“随机”本身不证明各选项等概率。实际随机结果发生前，不能承诺获得每条未来路线各自的最高收益。

默认只优化地图上的灵感拾取。奇点战斗额外奖励、隐藏携带物的返还、随机事件奖励，不在得到确认前加入计划收益。

## 已确认的游戏规则

以下规则来源分开记录。用户于本次需求中补齐了客户端没有实现的奇点 AI；客户端静态分析用于确认合法操作、层置换、触发时机和回合边界。

| 项目 | 规则 | 依据 |
| --- | --- | --- |
| 玩家普通移动 | 只在当前面。终点满足 0 < 曼哈顿距离 ≤ 当前步距；默认相邻一格 | DataModel 的 ShowCanMoveOutline 和 CanMoveToCube |
| 奇点普通移动 | 只从当前面上下左右相邻格中选择，不能普通跨面移动 | 用户明确确认 |
| 奇点同面追击 | 与玩家同面时，只选择使曼哈顿距离减少一的邻格；存在两条最短路径时随机选其一 | 用户明确确认 |
| 奇点不同面移动 | 枚举当前面的所有合法相邻格作为随机候选 | 用户明确确认 |
| 奇点旋转 | 随机选择合法层旋转，不因同面追击改变选法 | 用户明确确认；DataModel 的 GetBossRotData 提供执行映射 |
| 玩家操作顺序 | 移动和旋转可交错；各一次的普通回合同时考虑先移动后旋转、先旋转后移动 | ViewFunction 的两个模式入口、DataModel 的 CheckRoundEnd |
| 层旋转范围 | 四个常用方向对应当前角色所在行或列的层，正反各 90 度 | RoleCtrl 的旋转按钮和 DataModel 的层选择 |
| 旋转的数据影响 | 格对象、节点内容、灵感以及附着于该格的玩家或奇点同时被置换 | RubikCube 的置换与 RefreshCubeLabel |
| 奇点行动顺序 | 先移动；移动到玩家格立即进入奇点战斗；未相遇才吞格并继续旋转 | Controller 的 TryBossRound 和 StartBossEvent |
| 最后一回合 | 优先执行奇点缓存行动，完成后才扣回合并检查耗尽 | Controller 的 TryShowNextRound |

玩家步距、每回合移动次数、旋转次数和总回合数可能受道具或事件改变。普通各一次是首版基线；额度与基线不符时必须使用实际值或明确返回不支持，不能继续套用固定回合模型。步距大于一时，客户端直接移动到选定终点，中间路径上的格子不逐一触发拾取。

### 灵感的固定含义

灵感没有自主移动，但附着于格对象，随该层一起旋转。因此不能把初始 face、row、col 作为永久位置。层旋转对所有槽位应用同一双射，原先不同格的玩家与灵感、奇点不会仅凭一次旋转首次重合。

奇点移动进入自由灵感格时，客户端先播放灵感模型消失的动画，再将该格 item 合并到奇点格的携带物中；同 ID 的数量可累加。灵感标记随后隐藏并随奇点移动。这个过程不向玩家发奖励，不能把消失标记当成已收集。计数函数仍将奇点携带物计入未获取数量。

玩家主动进入格子时，移动回包和移动完成流程会处理拾取、清 item、发起节点事件。进入奇点格也经过这条流程，但吞入物是否返还以及具体数量由服务器奖励决定，客户端静态逻辑不足以保证。因此将自由灵感、奇点携带灵感、玩家已确认收集量分开记录。

### 同面相邻是确定的会合条件

玩家完成本回合全部操作后，若玩家与奇点同面且曼哈顿距离为一，奇点唯一能缩短距离的邻格就是玩家格。它移动后立即触发战斗，后续随机旋转不再执行。这个条件在最后一回合仍有效。

判定必须使用玩家最后一次层旋转之后的坐标。玩家一定在自己选择的层上，奇点可能不在；同面时任意转动并不保证仍同面。搜索需要模拟该旋转，核验最终同面与距离条件。

## 规划状态与坐标

区分当前空间槽位 slot 与持续的格身份 tile。扫描输出采用 scan_local；规划器固定首次有效布局的逻辑坐标，视角拖动只改变投影。真正层旋转更新 tile 到 slot 的对应关系，角色移动改变占据的 tile。

首版决策状态可写为：

```text
State = (
    player_slot, boss_slot,
    free_inspiration_positions_and_ids,
    boss_carried_inspiration_ids_or_unknown_count,
    confirmed_collected_count,
    remaining_rounds,
    moves_left, rotations_left, move_distance,
    phase, rules_version
)
```

以灵感 ID 防止重复计数；数量使用可确认的单位，不默认一个标记永远对应一个单位。地图所有非目标节点的排列可另存，用于预测事件类型、筛选执行能力和辅助识别；主目标的几何搜索无需把无关图标纳入每一个缓存键。

未知角色位置、未知灵感状态、坐标身份冲突或不完整布局，不得生成宣称完整的计划。奇点已吞入但看不见的灵感需由动作历史与任务进度维护；一次新扫描不能仅凭“没有黄环”认定已经获取。

### 层旋转的计算表示

使用扫描器明确的面法向 n、列轴 u、行轴 v。三阶魔方的逻辑格点为：

```text
p = n + u * (col - 1) + v * (row - 1)
```

选择经过行动角色的层，绕当前面的一个切向轴正转或反转 90 度；对该层中的格点 p 和法向 n 同时做整数旋转，再反算面、行、列。其余格子不变。玩家、奇点、自由灵感和节点排列使用同一个置换。视觉投影模型中的 DISTANCE 是渲染几何参数，不应代入逻辑层转。

此表示是客户端数组置换与轴角规则的数学归纳，实施时还需核验置换方向。客户端 face 数字、x/y、一基坐标与扫描行列存在轴向和镜像差异，执行端不能直接对 row/col 加一。规划器可始终使用自己的逻辑基，按钮方向由当帧姿态与明确映射转换。

## 每个行动阶段的搜索

按实际阶段展开动作，保留动作额度，而不是只把一轮表示为“走到某格”。普通各一次的玩家阶段最多先枚举移动后四种旋转，也枚举四种旋转后各可走格；相同结果状态合并。

玩家移动步骤先检查是否进入奇点格。如果相遇则立即到达终点，不强行补完剩余操作。如果进入自由灵感格，则产生候选拾取收益，并更新未收集集合；运行时只有拾取完成和奖励确认后才提交该收益。层旋转只搬运数据，不产生新的拾取。

玩家操作额度耗尽后，枚举奇点动作：

```text
if player.face == boss.face:
    boss_moves = 当前面内距离玩家恰好减少一的邻格
else:
    boss_moves = 当前面内全部上下左右邻格

for destination in boss_moves:
    if destination == player_slot:
        记录相遇终点，停止该分支
    else:
        结算吞格与吞灵感
        枚举以新奇点格为中心的四种层旋转
        同时更新玩家、奇点和灵感坐标
        完成本轮，remaining_rounds 减一
```

不同面时最多四个移动候选，再各有四种层旋转，普通敌方阶段最多形成十六个原始分支。同面时最多两个趋近移动候选；同面相邻时直接终止，没有旋转分支。去重后通常更少，具体计算耗时需实施后测量。

若动作额度或奇点行动受道具影响，候选生成器必须使用对应规则版本。不能用单移动、单旋转的上述数量当成所有情况下的固定上限。

## 有限回合搜索与最优性

采用带记忆化的有限深度搜索。玩家节点选择收益最高的合法行动，奇点随机节点保留全部可能结果。默认对随机节点取最小收益，求在最不利随机结果下仍然按期完成的最佳策略。

成功终点的值为本规划期间拾取的灵感数；预算内没有相遇的终点值为不可行。玩家节点取最大值，奇点节点取最小值。如果某个随机分支不可行，则该行动不能被标为保证会合。已收集量在实际状态中保存，搜索的收益增量只累计一次。

同面相邻条件提供提前终止：玩家剩余操作已耗尽、且这一条件满足时，可以直接判定本轮奇点移动会触发会合。普通 Manhattan 距离可用于同面追击分支和动作排序；不能直接当成跨面的真实剩余回合距离。

减少计算量的办法为：

- 预计算各面、各行列、正反层旋转的槽位置换。
- 对灵感状态使用位集合，对相同状态和相同剩余额度缓存搜索结果。
- 合并不同操作顺序产生的相同最终状态。
- 在规则与目标共同允许时，以魔方整体旋转对称规范化状态。
- 使用忽略奇点干扰的玩家最短会合下界剪掉预算必不足的分支；该下界必须经过模型核验，不能用经验距离替代。
- 当前已得到的可行收益达到“已拾取加全部剩余可拾取灵感”上界时，停止收益方面的继续搜索；同收益的最早会合仍需按对应目标处理。

完整搜索结束才报告 proven_optimal。设置计算预算时，超时可返回已验证的可行策略和已证明收益，但须报告最优性尚未证明。如果没有已验证的可行策略，返回未求解，不能把一个看起来接近的动作作为保证方案。不同回合预算下可输出最多保证拾取数、最早保证相遇回合与下一步动作，便于人工核对。

## 输出策略与逐步执行

输出由当前动作和后续分支组成。例如，“先转某层，再向某格移动；奇点结果为 A 时执行分支 A，为 B 时执行分支 B”。界面可显示一条代表性路线，但必须同时显示其他随机结果对应的处理，不能把代表路线当作唯一未来。

建议结果字段为：

```text
status: solved | no_guaranteed_plan | search_budget_exhausted | blocked
objective: max_guaranteed_inspiration_with_encounter_by_deadline
turn_budget
guaranteed_inspiration_count
latest_guaranteed_encounter_round
proven_optimal
next_action
contingent_policy
rule_assumptions
unresolved_state
```

规划器每次给出一个逻辑动作；执行器使用当帧画面定位移动蓝框或层旋转按钮，等待结果确认。事件结束、动作额度改变、灵感拾取、奇点行动后，重新校验状态并选择对应策略分支；观测与模型不一致时重新计算。

## 与现有识别和执行流程接入

现有 single_run 执行器固定从移动阶段开始，移动和旋转共用随机选择函数。接入时需要把动作选择与界面执行分开，让规划器决定下一种操作，而执行器保留按钮、预览确认、节点事件、奖励和战斗的处理能力。

扫描结果的 geometric_neighbors 包含跨面表面邻接，不能作为合法普通移动边。当前像素点击点也不能跨动作复用，因为玩家面切换、重置视角和选择模式可能改变相机。

每回合重新扫描整个魔方会重复付出约五十秒的观察成本。设计采用首次完整扫描、随后应用已确认层置换与节点变化，再用少量关键视图核对玩家、奇点和灵感。奇点阶段结束后的候选状态至多包含普通模型的十六种结果，可用角色位置、图标排列和关键格可见内容消歧；出现相同外观或遮挡时继续补看，仍无法确定才回退完整扫描。

逻辑地图坐标保持不变；新的几何跟踪会话与该地图建立显式对应，不把重置后的新 scan_local 标签直接拼接进旧地图。新位面、新局或无法恢复的身份冲突需要重新建立地图。

事件可能改变额度或移动位置。首版规划针对已确认的常规动作规则求解，事件发生后以实际结果重算。若要在事前保证包含所有随机事件的成功，还需要事件结果的完整分支模型；仅有目标位置无法提供该保证。未支持事件和未知目标底图应明确记录为执行风险，不能通过伪造业务节点语义解决。

## 实施顺序

先实现与游戏输入分离的规则模型和求解器，读取现有 layout JSON 与回合参数，输出可人工查看的策略。随后在 3D 查看器中展示逐步层转、移动、灵感状态和奇点分支，让用户比较逻辑结果。

模型明确后再接现有执行器，支持两种操作顺序与每个动作后的状态提交。最后接增量识别和奇点随机结果消歧。这样可以分别定位规划错误、坐标映射错误与输入未生效，避免把三类问题混在同一实机结果里。

本设计阶段没有操作游戏。后续用户要求回合和收益统计，已进行离线状态穷举、动态规划与独立随机轨迹复核，结果与边界见[第一位面数值计算](resonance-pc-deep-dive-planning-statistics.md)。实机验证仍应重点核对两种操作顺序、层置换镜像、灵感随层移动、奇点吞入灵感、同面两条最短路径、最后一回合撞入玩家，以及实际结果偏离候选模型后的重规划。
