# PC 垃圾回收的点击确认与补点

货运到站附加操作和内部 `rubbish_recycling_pc` 任务共用
`resonance_pc.execute_rubbish_recycling_from_city_panel`。动作从城市面板进入垃圾中心，
确认没有垃圾后返回同一城市面板；货运只有收到完成及返回的视觉确认才继续。

## 页面证据

`_rubbish_recycling_vision.py` 每轮只截取一次 1280×720 RGB 图，所有 ROI 均来自这帧。
城市身份复用 `_city_panel_vision.probe_city(source_image=...)`，不另外截图。

识别优先级是奖励层、回收页、站内菜单、城市面板：

| 状态 | 正向证据 |
| --- | --- |
| 奖励层 | “恭喜获得”和“触碰空白区域退出”同时命中 |
| 有垃圾 | “回收所有垃圾”命中 |
| 没有垃圾 | “现在没有垃圾”命中 |
| 站内菜单 | “垃圾回收”入口命中 |
| 城市面板 | 预期城市徽章、垃圾处理中心文字及返回按钮同时命中 |

奖励只出现一个锚点，或两个回收状态按钮同时命中时，判为未知；没有按钮也判为未知。
底层城市徽章或菜单残留不能覆盖已识别的更深页面。按钮消失不能证明进入或回收成功。

城市垃圾处理中心文字来自用户提供的远星大桥截图，裁片、掩码及来源说明位于
`templates/recycling/controls/station_label*`。搜索区域围绕城市配置的垃圾中心坐标，
只用标题确认入口可见，点击仍使用该城市坐标。
奖励双锚点显式复用现有通用获得奖励素材，保持既有识别参数。
荒原站文字及垃圾回收奖励布局尚无本轮实机校准结果；识别不明时只等待并超时报错。

## 状态转换

| 阶段 | 允许点击的原状态 | 点击 | 目标状态 |
| --- | --- | --- | --- |
| 进入垃圾中心 | 城市面板 | 城市配置的垃圾中心坐标 | 站内菜单，或已进入的回收页 |
| 进入回收页 | 站内菜单 | 重新匹配的垃圾回收入口 | 有垃圾 / 没有垃圾 |
| 一键回收 | 有垃圾 | 重新匹配的一键回收按钮 | 奖励层 / 没有垃圾 |
| 关闭奖励 | 奖励层 | 空白位置 `(500,500)` | 没有垃圾 / 有垃圾 |
| 返回菜单 | 没有垃圾 | 当帧返回按钮 | 站内菜单 / 城市面板 |
| 返回城市 | 站内菜单 | 当帧返回按钮 | 预期城市面板 |

每次动作前后都要求两帧连续识别一致，页面锚点中心变化不超过 2 像素，
避免入口仍在滑动时按城市固定坐标点击。已到目标状态则不再点击。
关闭奖励后如果仍有垃圾，只重试回收阶段，不重新进入城市或重跑整个任务。
返回时如果一次已直接到城市，立即停止，不再按固定次数点击返回。
只有确认“没有垃圾”并确认返回城市，才返回 `success=true`、`final_state=empty`、
`page_state=city_panel` 和 `returned_city_panel.confirmation=observed`。
`reward_overlay_seen` 仅表示实际识别过奖励，不再根据回收成功推断。

## 预算及诊断

- 轮询间隔 0.3 秒；点击后至少留 0.5 秒响应时间。
- 普通点击后 3 秒内不补点；关闭奖励的补点间隔为 1 秒。
- 每阶段最多 3 次点击（含首次），总时限 12 秒；整个回收流程总时限 90 秒。
- 阶段重入不重置时间和次数预算。未知状态不授权点击，超时后也不接受迟到识别结果。
- 截图、匹配或点击技术错误立即作为失败报告，不转换为按钮未出现；取消请求可中断等待。

`[RubbishFlow]` 日志记录阶段、当前状态、次数、坐标、补点原因、置信度及耗时。
异常详情保留最后观察、已完成转换和点击历史，由框架现有失败证据机制处理截图。
