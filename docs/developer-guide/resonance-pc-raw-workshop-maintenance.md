# 原料车间维护（PC）：执行入口与边界

2026-10-11 实现。本文取代旧基础任务草案中关于原料领取、固定人数和先识别普通总览的流程；不改变其他房间的草案。

## 公开入口

`tasks:maintain_raw_material_workshop_pc.yaml:maintain_raw_material_workshop_pc`，标题为“原料车间维护（PC）”。从 **1280×720 客户区的普通整顿中心总览** 开始；运行结束停留当前原料车间，不自动返回。

- 必填 `room_name`：植物纤维原料车间、动物纤维原料车间、缝纫工具原料车间、人造纤维原料车间四选一。
- `max_reserve_rounds`：整数 1～8，默认 8；是生产中补替补轮数的上限，不是人数。
- `max_search_steps`、`settle_sec`：沿用已实现房间地图导航的参数，默认 12、0.8。
- 配方由用户在游戏中设置，本任务沿用当前配方，不选择新配方。

实际任务导航仍调用 `open_reforming_center_room_pc`。`aura.run_task` 当前返回子任务的框架数据，业务导航结果取 `nodes.navigate.output.nodes.open_room.output`，不能把父节点执行成功视作房间进入成功。

## 顺序与有限循环

任务 YAML 负责顺序与提前停止；Python 原子动作负责一次操作与反馈。

未生产：进入房间 → 稳定观察 → 预存最多 → 补工作一次 → 补替补一次 → 重新观察 → 能开始则开始一次 → 最终观察与汇总。

生产中：进入房间 → 稳定观察 → 补替补／观察转入工作名单 → 有实际进展且替补仍有空位时下一轮 → 最终观察与汇总。最多 8 轮。工作和替补同时满、无可用人员、选择会减少原名单、无进展、替补保持满但工作仍缺、识别未知或轮数用尽，均停止补人。

框架 `while` 当前不暴露前一轮业务输出，因此使用 `reserve_round_1`～`reserve_round_8` 的有限顺序链，根据上一轮 `safe_to_continue` 和 `continue_reserve` 分支。没有全局共享计数器或框架修改。

已知缺人但页面仍可信可以继续后续维护；未知状态不继续写操作。开始按钮灰色返回 `blocked/start_disabled`；已有生产不点开始。既有人员不撤出；空选择或少于当前名单的选择不提交，用已确认选择页的左上返回退出。已有“一键取消”不会被点击。

生产中不预存、不编辑工作名单、不终止、不加速。本任务也不领取产物、不改配方、不建设、不解锁、不战斗抓人。产物按用户说明由游戏自动入仓。

## 点击与确认

全部坐标为客户区坐标，并取 5 的倍数。

| 操作 | 坐标 |
| --- | --- |
| 预存／最多／确定 | (400,440)／(895,380)／(960,535) |
| 工作／替补页签 | (730,300)／(1060,300) |
| 选择囚犯／一键选中／确认 | (885,670)／(935,670)／(1150,670) |
| 开始生产／选择页返回 | (265,675)／(95,40) |

房间标题与按钮中心的动态定位坐标也取 5 的倍数，房间点击取整后仍须位于已有安全 ROI。地图定位、路径与拖动算法保持不变。

每次点击记录输入尝试和返回信息，`app.click()` 返回 `None` 只表示调用返回，输入确认仍为未知。先从新截图确认点击效果，再用另外两张连续语义一致的新截图确认界面就绪。每阶段 0.5 秒轮询、最多 5 秒；消费／选人提交和开始生产都不自动重试。

一键选中需要按钮变为“一键取消”或人数增加作为效果证据。人数为 0 且按钮未变化不算点击成功，也不能伪装为“已确认无人”。预存点最多后检查原生滑块右端位置；提交后只记录 `submitted`，不虚构存满金额或真实费用。已满黑条是另一条明确的跳过分支。

## 识别与结果

截屏在输入边界统一 RGB→BGR 一次。UI 控件使用游戏截图模板，人数使用原生字体的 0～9 和斜杠单字符库，不使用 OCR，也不匹配整组固定的 `7/7`、`2/2`。

工作、替补和选择页的人数 ROI 跟随匹配的文字标签，支持两位数；只有合法 `current/capacity` 才判断满员。稳定状态去掉会轻微抖动的模板分数，只比较业务值。开始按钮还检查蓝色／灰色，不能仅凭灰度字形把禁用按钮当可用。生产中房间就绪使用房间标题、名单标签及“终止＋加速”，不要求不存在的“选择囚犯”。

任务输出 `success/status/reason/room_name/snapshot/data`：

- `completed`：最终确认生产中且工作、替补都满；`success=true`。
- `partial`：生产中但仍有人员缺口，包括轮数耗尽；`success=false`。
- `blocked`：页面可信但生产未启动，如开始禁用；`success=false`。
- `failed`：导航、点击或观察未确认；当前 `snapshot=null`，先前可信快照仅保留在 `data.last_confirmed_snapshot`。

所有步骤结果按实际执行顺序汇总；最终观察优先，不能让旧开始／补人快照覆盖新状态。`safe_to_continue` 控制流程，不用框架节点成功来替代业务完成。
