# PC 识海深潜开发记录

## 第二阶段：多角度棋子定位

状态：方案已确认，尚未接入任务执行器。

### 观察角度

以重置视角后的状态为 `0 px`，向上拖动魔方。拖动距离与魔方偏转角度按实机测试呈正比例关系。

根据 `80 px` 小步拖动测算结果，四角度采集任务按当前灵敏度选择一组累计位移。GUI 默认选择慢灵敏度：

| 灵敏度 | 四个累计向上位移 |
|---|---|
| 慢灵敏度 | `560 / 2480 / 3680 / 5600 px` |
| 快灵敏度 | `280 / 1280 / 1920 / 2880 px` |

若从 `0 px` 开始按升序连续移动，各段相对位移为：

```text
0 -> 560:      560 px
560 -> 2480:  1920 px
2480 -> 3680: 1200 px
3680 -> 5600: 1920 px
```

快灵敏度各段相对位移为：

```text
0 -> 280:      280 px
280 -> 1280:  1000 px
1280 -> 1920: 640 px
1920 -> 2880: 960 px
```

任务启动后先等待 `2s`。单次拖动最多 `320px`，较长区段拆分为多个 `320px` 和余数；分段之间等待 `0.2s`。每到达一个目标位移后等待 `0.4s` 并截图，截图后等待 `0.2s` 再进入下一角度。零位视角不执行棋子识别。

### 联合识别方案

- 四个角度的截图都同时搜索玩家棋子和敌方晶体，不再拆成两个观察流程。
- 每个角度分别维护可见面的格子投影表，并将画面槽位映射为统一的 `(face, row, col)` 逻辑坐标。
- 玩家与敌人使用各自独立的模板和遮罩，但共享截图、角度状态和槽位映射。
- 玩家棋子的内缩躯干遮罩和边缘匹配实验仍可作为模板制作参考，但原固定初始视角的模板尺寸、锚点公式和阈值不得直接沿用。
- 每张截图允许同时产出玩家候选和敌人候选；任一对象唯一确认后，在后续角度中只继续寻找尚未确认的对象。
- 玩家和敌人都得到唯一逻辑坐标后可以提前停止后续观察。
- 四个角度结束后仍有对象未确认或存在冲突时，返回“位置不确定”，不得猜测位置或继续规划玩家操作。

### 待标定内容

- 四个观察角度各自的可见面编号、九宫格槽位中心和 ROI。
- 四个角度下玩家棋子的模板、遮罩、阈值和稳定帧规则。
- 四个角度下敌方晶体的模板、遮罩、阈值和动画稳定帧规则。
- 视角到达判定、拖动累计误差和必要时的重置策略。
- 玩家与敌人处于同一格或互相遮挡时的相遇状态判定。

### 框架接入注意

`VisionService.find_template_async` 和公开 `find_image` 支持遮罩，但当前公开异步 `wait_for_image` 没有转发 `mask` 参数。实现第二阶段观察 action 时，需要选择异步安全的遮罩匹配调用方式，不能在 async action 中直接调用同步视觉 action。

### 灵敏度探测素材采集

GUI 小任务“数据采集”中的“采集灵敏度素材”用于建立快、慢两种视角灵敏度的数据集。该任务没有参数，也不负责判断或标注灵敏度：

1. 启动后等待 `2s`。
2. 通过框架公开 `plans/aura_base/drag` 从 `(640, 480)` 拖动到 `(640, 160)`，只执行一次 `320px` 拖动。
3. 等待 `0.4s`，保存一张完整的 `1280x720` 客户区截图。
4. 复用四角度素材采集的截图 Action，图片写入 `logs/test/320/`，文件名为 `320_<时间戳>.png`。

任务不会重置视角，也不会移动或覆盖已有图片。每次采集前由测试者手动恢复初始视角，采集完成后再将图片人工分类。
