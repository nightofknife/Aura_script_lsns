# PC 观察边界修复

本轮修复三批代码整理复核确认的五类原有问题。识别配置、模板、任务、消费确认和记账实现保持；深潜及其共用依赖继续冻结。

## 便当回顶

消费端在原扫描截图内裁出视口，使用现有内容与工作餐模板判断，不调用恢复盘点。内容加载并稳定后才能拖动，达到原连续静止次数后还须正向识别三个工作餐槽位，才授权固定槽位定位。中途静止、缺槽、页面消失和迟到观察均停止。原 ROI、阈值、拖动参数、次数、页面与总时限保持。

## 黑月截止时间

源/目标识别和稳定帧比较结束后再次检查截止时间，达到截止时间的结果不能授权点击或成功。保留每次独立 7 秒探测、30 秒只读购买等待、轮询、补点次数和取消异常。同步截图无法被强行中断；其迟到结果会被丢弃。

## 原生生成器发布

full 与 prepare-only 先在仓库 `.pytest_tmp` 内暂存，检查控件、商品覆盖、声明文件、可解码图片和摘要后再发布。缺 catalog、部分提取失败、blocker 或资源不完整均不发布。发布和旧资源清理失败时恢复原 manifest、图片与来源文件。

prepare-only 只重建准备控件，保留当前 normal 商品输入与来源。完整生成配方及识别参数保持，保留图片使用字节比对验收；不会恢复已退休资源。

## 结算与归位

内部结算观察区分有效命中、有效未命中和未知。截图失败、空图、尺寸/类型不符、异常或非有限匹配结果属于未知，不证明页面消失。

- `settlement_confirmed`：已正向识别交易结算。
- `closed` / `final_absence_verified`：关闭后获得有效未命中证据。
- 买入返回 `shop_page` 前另需原商店模板连续确认；成功结果含 `bought_confirmed` 和 `shop_ready`。

已确认结算或初次观察未知时，不再进入 OCR 买入确认分支。只有明确未出现结算且正向识别预计买入确认面板时，保留原一次确认操作。关闭失败、商店未确认或取消均停止，不重新提交交易；错误详情保留已确认交易、结算证据及实际采买书结果。

乘客关闭前重新确认结算仍在，技术失败立即停止。有效确认结算已消失后只读检查城市入口和主页面，不继续向未知页面发送关闭点击。原模板、阈值、关闭次数和等待参数保持。

## 气泡水资源

消费前显式检查模板与 mask 非空、维度、uint8 类型和原尺寸约束；文件读取/解码失败转为包含资源名称的 ValueError。COLOR/UNCHANGED flags、路径边界、加载顺序和消费保护保持。

## 验证

先在旧实现验证失败回归，再验证修复、现有消费保护、黑月准备/退出、生成器失败保留旧库及交易流程。所有检查从仓库根目录运行，pytest 与其他临时输出均位于仓库内；离线结果不代表实机验收。
