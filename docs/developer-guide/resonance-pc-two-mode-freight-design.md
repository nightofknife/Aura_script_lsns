# PC 货运两模式现行契约

本规范取代四模式方案中的模式划分。用户入口只接受 `free`（不定线路）和 `fixed`（固定线路），默认 `free`。`profit / quick / target` 不再作为运行模式或兼容别名。本文对应代码与离线测试；不代表实机验证。

## 线路与目标

| 设置 | 不定线路 free | 固定线路 fixed |
| --- | --- | --- |
| 路线来源 | 在可选城市中自动规划完整路线 | 按有序城市列表推进，保留重复访问 |
| 默认优化目标 | 最高预计收益，再少疲劳、少书、少协商、少航段、稳定顺序 | 最大化不超过预算的预计疲劳，再最高收益、少书、少协商、少航段、稳定顺序 |
| 预计收益目标 | `target_profit=null` 或省略时不启用；正金额启用最低疲劳达标搜索 | 不参与规划，不提交 |
| 结束城市 | 自动或指定允许的终点集合 | 选定的合法线路前缀末站 |
| 循环 | 由精确搜索决定，可重复城市 | 闭环沿原顺序循环，允许最后部分圈；开放线路最多沿给定线路推进一次 |
| 起点 | 正式运行识别实际城市 | 可选先定位至线路起点；定位疲劳计入整任务上限 |

不定线路仍在开跑前冻结市场、账号数据并规划完整路线，不因为名称变成“不定”就逐站变更线路。启用收益目标后，在全部约束及合法终点条件内最小化预计疲劳，其后少书、少协商、少航段、稳定顺序；超额利润不作为平局目标。不可达只返回实际可达最高收益诊断，执行路线为空。

固定模式保留已有停止规则，不接收执行次数。至少有一段有效贸易才形成货运计划，可包含明确的空载导航段。零/负消耗线路显式拒绝；循环边界从正消耗和预算推导。

## 用户参数

- 疲劳预算：默认700；货舱：默认750。
- 用书：不用 / 限量 / 无限。运行唯一字段 `book_budget` 为0 / 非负整数 / null。
- 每本最低增量收益：默认500000（GUI 50万）。每本增量必须严格正且达到下限，前缀逐本达标；不能用平均收益补足。
- 用书策略：`profit` 显示“收益优先”，`fill` 显示“尽量满仓”。尽量满仓受书数和单本收益限制，首次满仓后停止加书，不为替换商品继续用书。
- 协商策略：`auto / required / disabled`。与用书策略独立，尽量满仓不强制协商、不自动取消书数上限。
- 不定线路：`available_city_ids / required_end_city_ids / target_profit`。
- 固定线路：`fixed_route_city_ids / reposition_to_route`；后者默认false。
- 账号：声望、商品解锁、砍价/抬价成功率序列与幅度，复用既有模型。
- 执行与附加：协商尝试次数、等待超时、投资/回收/拣货、用药、汽水/便当。蜃息岛投资默认开启；交易品投资沿用独立开关；恢复默认关闭。

采用原 Fraction 协商期望疲劳和满20%定价模型。协商尝试耗尽仍按实际达到价格成交；首站已有货物不抬价，其清仓收益不计入路线目标。

## GUI 联动与提交

共享纯规则位于 `packages/resonance_shared/freight_parameters.py`，原计划服务路径仅保留兼容导出。GUI不得静态导入 `plans`，以保证冻结包的计划保持外置：

- `FREIGHT_MODES` 定义两个模式。
- `FREIGHT_PLANNING_KEYS` 标识影响规划的字段。
- `effective_freight_inputs` 将保存的表单投影为有效运行参数，不改写保存值。
- `freight_control_state` 提供控件依赖状态，GUI 再统一叠加运行中的锁定。

| 条件 | 联动 |
| --- | --- |
| 不用书 | 本数、策略、阈值禁用；运行省略无效策略和阈值，后端使用规范默认值 |
| 限量 | 本数、策略、阈值启用；额度覆盖整条路线 |
| 无限 | 本数位置显示无限，策略和阈值仍可编辑 |
| 固定模式 | 显示有序线路和定位，隐藏城市范围/终点/收益目标；保存值保留 |
| 不定模式 | 显示城市范围、终点、收益目标开关；隐藏固定线路与定位 |
| 收益目标关闭 | 金额禁用并保留；运行不传目标 |
| 收益目标开启 | 必须正金额；疲劳预算仍生效 |
| 不协商 | 尝试次数禁用，运行不传该设置 |
| 便当关闭 | 类别与排序禁用，运行不传优先级 |
| 汽水、便当都关闭 | 恢复下限禁用，运行不传该设置 |
| 用药关闭 | 药品及次数禁用，运行不传这些细项 |

`target_profit_enabled / books_enabled / books_unlimited / finite_book_budget` 仅是持久化的界面状态，不是额外运行参数。隐藏/禁用不清空原值，重新启用恢复原值。用户明确不需要旧配置兼容：不做旧模式或Auto Book格式的映射、迁移或专用确认流程；只支持新配置内部的参数保存恢复，不删除用户已有配置文件。

终点城市被移出可选城市时，保留冲突选择并提示；用户可取消该终点或重新选择城市。冲突解决前禁用试算/启动，不静默改终点或自动终点。固定线路显示闭环/开放提示。

影响规划的有效参数变化，使已有预览标记“需要重新试算”；投资、倒垃圾等不改变规划的开关不触发重算。正式运行仍刷新行情、识别实际起点后重算。旧预览不是直接执行依据。

## 服务、任务与结果

服务入口仍为 `ResonancePcTradePlannerService.plan_optimal_route`，纯求解入口仍为 `ResonancePcExactTradeSolver.solve`。两者默认 `trade_mode="free"`；free 是否执行目标搜索由 `target_profit is not None` 决定。fixed 忽略非本模式字段，缓存也排除它们。

任务 `auto_cycle_trade_pc.yaml`、`preview_trade_plan_pc.yaml` 以及保留的组合任务内嵌货运 schema 均只允许 `[free, fixed]`。`book_budget` 和 `target_profit` 明确允许 null；不用巨大预算或0金额伪装无限/目标关闭。

返回保留 `route / buys / books_used / bargain_to_cap / raise_to_cap`、每段 `loaded_quantity / book_stop_reason` 和原 `*_exact` 字段。模式统一返回 free/fixed。

- 有目标的free结果继续带 `target_profit / target_reached / target_gap / maximum_reachable_profit`；没有目标不返回达标断言。
- fixed结果继续带完整圈数、最后部分圈、结束位置和剩余预算。
- `reposition_route` 与贸易route分离；总预计疲劳已经包含定位，不能再次相加。
- 城市访问的卖货意图来自上一条贸易边，末站只卖不买，重复城市通过访问索引区分。
- 规划状态保持 `ok / no_plan / target_unreachable / fixed_route_infeasible`；状态名中的target描述未达标原因，不是第三种路线模式。
- action适配器将 `no_plan` 映射为 `no_profitable_route`。起点不符且未开定位时入口返回 `fixed_start_mismatch`；直接solver仍报ValueError，service包装为参数错误。

## 验证范围

保留并更新了250组小图独立全枚举对拍：不定最大收益、不定目标收益、尽量满仓配合协商、固定疲劳目标，共1000组目标/策略组合；适用场景对照dense/sparse，核对完整平局规则。

新增/调整验证覆盖：旧模式拒绝、free可选目标与nullable schema、固定忽略旧目标、隐藏书设置的缓存等价性、GUI/任务共享有效参数投影，以及真实服务经预览/运行action调用的一致性。GUI联动、布局与配置恢复由“gui调整”线程负责并单独记录。

所有测试和静态检查从仓库根运行，临时产物限于 `.pytest_tmp`。本次不提交发布产物、不打包、不运行游戏。


## v1.11.12 增量

满仓策略新增 `book_waste_limit`（非负整数，默认 0）。浪费是首次满仓时合格商品可购总量超过货舱的数量，边界包含等号；超限保留此前合法未满仓方案，不回退单本收益阈值。收益优先或不用书时忽略此参数，GUI 保留其草稿。整趟用书预算、固定线路必须完成盈利交易及不追加空载尾段的约束保持。目标收益模式的满仓策略在相同最低疲劳下优先更高收益，再依原平局规则选择。

执行选项新增 `auto_trailer=false`、`trailer_daily_first_n=1`、`trailer_payment=gold|mileage`，不进入求解器或试算输入。根据完成路线（含定位段）预选最长 X 段，实际执行时读取游戏当天配额；明确用尽或超出当天前 X 次资格后，本轮后续不再尝试。确认支付后未知出发或疲劳结果停止处理，不自动再次提交或普通驾驶。客运不使用拖车。详见 [拖车服务契约](resonance-pc-trailer-service.md)。
