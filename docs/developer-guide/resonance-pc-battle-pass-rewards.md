# 通行证奖励收集

入口：「独立功能 → 日常奖励收集 → 通行证奖励」。每日任务和通行证分别启动，
共用任务互斥、取消及结果展示，不增加合并启动或配置选项。
任务引用为 `tasks:daily_rewards_pc.yaml:collect_battle_pass_rewards_pc`，公开动作为
`resonance_pc.collect_battle_pass_rewards`。

## 执行顺序

1. 从 1280×720 站场主界面启动，用既有「启程」锚点确认主界面。
   同帧匹配完整的带红点星形入口，明确未命中时返回 `skipped_no_reminder`。
   识别技术错误或未知页面不能作为「没有红点」。
2. 点击入口，确认通行证页面。读取左侧实际可见的通行证名称，回到列表顶部后逐个处理。
   不固定名称、角色、数量，也不依赖左侧提醒红点。
3. 选择入口后，用左下大标题核对当前通行证名称，再切换到「任务列表」。
   **按照用户确认的规则，只判断任务「一键领取」按钮是否出现**；出现就点击，
   一次领取已完成的每日及每周任务奖励。没有按钮就进入等级奖励部分。
   不判断单张黄色任务卡、每日/每周子页、「未完成」或锁状态。
4. 领取后必须同时确认「获得物品」标题和空白区域退出提示，才在空白处 `(500,500)` 点击。
   确认弹层关闭且仍在该通行证任务页，再检查一键领取按钮。
5. 切到「环游手册」，只点击整体匹配到的带红点一键领取按钮，领取已解锁等级奖励。
   同样确认奖励弹层、关闭、重新检查，直到按钮不再带红点。
6. 当前通行证两部分均处理完才记录完成。向下滚动左侧列表，重读名称与位置，
   继续处理其他入口。确认到底且可见入口均处理完后，点击火车按钮，
   再次确认主界面才返回成功。

## 多通行证定位

原生 `ScrollGrid_Time` 是纵向、clamped 列表，参考客户区 ROI 为 `(12,75,200,427)`，
原生行距换算约 75.33 像素。`Group_Tab_000...006` 是复用单元，不能据此判断入口总数。
列表 `Txt_Name` 与左下 `Txt_Title2` 均绑定 `BattlePassFactory.topicName`，因此复用现有 OCR
读取动态名称，并核对大标题；不建立季节名称模板。大标题 ROI 为 `(45,485,265,75)`。
列表文字按左对齐起点过滤，避免把透出的固定「环游手册」标签当作另一个入口。

每次选择或滚动都用当前帧的名称与位置。列表边缘裁切行等待下一次有重叠的滚动再处理。
同名歧义、低置信度、空列表或标题无法稳定确认时停止，不据此证明列表结束。
回顶部和向下遍历都以连续两次手势后有效列表无位移确认边界，而非可见项数量。
滚动只发生在已确认的通行证页面，使用内部手势并停止惯性。

## 点击确认与限额

`BattlePassRewardFlow` 复用每日流程的 `transition`、`confirmed_page` 和 `observe`，
只替换读图器、错误上下文、超时及业务顺序。每日流程默认参数保持不变。

- 点击前连续两帧确认页面、当前通行证及目标；目标已出现时跳过点击。
- 点击后等待至少 1.2 秒，再连续两帧确认目标状态。只有重新确认原页面和按钮仍存在才能补点。
- 每次逻辑转场最多三次点击（首次加两次补点），总预算 15 秒。
  按钮消失不能单独证明领取成功，必须确认奖励弹层。
- 一个通行证每类奖励最多 16 次页面循环；最多处理 32 个通行证、64 次遍历循环，
  回顶部最多 16 轮，整个通行证任务预算 600 秒。
- 取消沿用框架停止信号；异常、未知页面或超时停止并保留当前页面，不盲点返回或报成功。

## 结果与素材

成功结果含 `success=true`、`component=battle_pass`、`returned_to_main=true`，
`status` 为 `collected`、`nothing_to_claim` 或 `skipped_no_reminder`。
`passes_processed` 是完整处理的通行证数，`passes` 含各名称与两类领取阶段操作次数。
`claim_clicks` 包含补点，`reward_overlays` 为实际确认的奖励弹层数，两者都不是物品数量。
异常带 `code/message/detail`，含最后页面、当前通行证、已处理项、点击和滚动次数。

运行素材位于 `templates/rewards/battle_pass/`，参数目录为
`data/meta/battle_pass_templates_pc.json`。保留已确认的完整带红点入口与共享弹层模板，
等级领取使用 float32 `.weights.npy` 遮罩，不可用二值预览 PNG 替代。
来源和重建命令见 `plans/resonance_pc/development/template_sources/rewards/battle_pass/README.md`。
发布收集器按整个 `templates` 目录收集文件，浮点遮罩无需新增打包规则。

本批仅实现代码与接入已审阅素材，遵循本地规则，没有新增或运行测试、编译、打包、
OCR/模板回放或实机领取。历史模板分数不代表整条自动化已经通过实机验证。
