# 生产车间收菜（PC）

任务引用：`tasks:collect_product_workshops_pc.yaml:collect_product_workshops_pc`，展示名“生产车间收菜”。起点和成功终点均为普通整顿中心总览，客户区为 1280×720。任务覆盖 1～6 号生产车间，无商品筛选、数量识别或其他业务输入；`max_search_steps` 与 `settle_sec` 沿用现有房间导航的技术参数。本任务默认允许 24 次地图搜索，覆盖远端车间。

## 流程与复用

1. 只读检查运行所需原生模板是否齐全。
2. 通过现有 `open_reforming_center_room_pc` 子任务进入 1 号生产车间，显式提取子任务 `open_room` 的业务结果；框架节点成功不能代替 `success=true`、`room_entered=true`。
3. 打开游戏原有“车间导航”列表，识别六个车间编号及各自开放状态，然后关闭列表并返回普通总览。
4. 按 1～6 号顺序处理。明确未开放的车间直接返回 `locked`；已开放的车间复用既有房间导航进入。
5. 在确认目标车间页面后识别“全部领取”。没有按钮记为 `no_collectable`；有按钮则点击一次，等待“制作完成”展示，关闭并确认恢复车间页面。
6. 若出现仓满丢失提示，取消领取，返回总览后以 `blocked` 停止本轮；未知页面、识别含糊、操作超时或返回未确认均停止后续车间。
7. 每间车间确认返回普通总览后，才继续下一间；最后由纯汇总动作返回本轮结果。

任务沿用现有截图、模板匹配、点击、停止信号处理、返回按钮与总览识别基础，不另建导航、输入或返回机制。初次进入 1 号车间仅用于读取原生导航的开放状态；扫描完成先回总览，再按统一的逐车间流程处理，避免扫描步骤同时领取。

运行时只读取打包模板并操作 UI，不读取游戏运行时内存、调用游戏内部接口或按玩家等级推定开放状态。此前原料车间维护和生产车间补人中的业务步骤不直接挪用：它们的前置状态、保存和结束条件不同。

## 开放状态识别

游戏 `UIPrisonMainViewFunction` 绑定的导航列表包含六个车间条目。未开放条目使用 `Group_Lock` 状态，表现为灰色卡片、灰色编号和“暂未开启”文字；没有独立挂锁图标。开放与当前选中状态分别识别，选中车间属于开放车间。

六个编号与状态都必须明确，才能开始领取。不能把模板缺失、不可见或匹配失败解释为 `locked`；已开放房间导航失败同样属于失败。扫描得到的开放状态在本次运行内复用，不进行解锁或建设。

## 领取与结果边界

每个已开放车间最多点击一次“全部领取”，不等待生产倒计时，不使用加速券、不逐个领取工位，也不识别本次获得的商品或数量。按钮没有出现只有在目标车间页面已明确时才代表无可领取产物；页面无法确认应报告失败。

领取后出现“制作完成”展示才按领取反馈继续；不因“全部领取”仍在就重复点击。容量丢失提示只取消，不确认丢失，不继续后续车间。返回后必须确认普通总览，不能仅凭返回按钮点击成功就报告结束。

逐车间状态为 `collected`、`no_collectable`、`locked`、`blocked` 或 `failed`。整体返回 `success`、`status`、`reason`、`results`、`unlocks`、`visited_count`、`collected_count`、`skipped_count`、`returned_to_overview`、`page_after` 和 `stopped_room`。全部已开放车间都无可领取产物属于正常完成；失败或阻断保留已有结果。未执行车间不能补成已检查或已跳过。

YAML 以 `safe_to_continue=true` 串联后续车间，依赖节点允许 `success|skipped` 使分支跳过后仍可汇总；动作输出中的业务状态决定是否继续。资产检查和汇总只读，扫描及逐车间领取动作会进行游戏输入。

## 模板来源与当前验收边界

领取按钮、领取展示、仓满提示和取消按钮来自游戏原始精灵、内嵌字体、Prefab 布局与文本配置。3～6 号车间标题以及 1～6 号导航卡片的开放、未开放、当前选中状态采用同一原生合成方式。此前审阅的来源记录位于仓库 `.analysis_tmp/prison_collection_native_20261020/` 与 `.analysis_tmp/prison_workshop_unlock_native_20261020/`；运行时使用正式打包素材，不依赖这些审阅目录，不使用模糊录像裁片。

原生合成的导航卡片是状态样例，不能代表当前账号的实际开放状态。既有导航素材与操作的复用也不意味着新增车间、开放识别和领取流程已经实机验收。

3～6号车间的地图节点由当前游戏总览 Prefab 中同父 RectTransform 的相对偏移及既有2号车间锚点推导，已标注为原生布局提示，未冒称实测坐标。定位继续优先使用原有实测锚点，只有当前截图中目标标题实际命中并进入安全点击区后才点击。

按用户要求，本次实现没有新增测试代码，也未运行测试、模板匹配验证、冒烟或游戏实机操作。模板阈值与完整收菜流程仍待后续获准后验收。
